# 3000人进图Admission批量A/B

## 测试口径

- Windows IOCP，1 MapHost、16 Gate、1 Login、1 LoginMgr、1 Location。
- Rust客户端，3000人先完成连接/Login，再同时发起Map Enter。
- 所有玩家位于同一AOI Grid，使用正式`full`进图语义，初始视野经`C2G_MapSnapshotReady`和`G2C_AoiDelta`下发。
- 入场结束后运行5秒Probe Only，每玩家0.2Hz；该短窗口用于故障诊断，不用于稳态CPU容量判断。

## 结论

初始视野从大型`EnterMap`响应解耦后，四档都能完成约449.85万次同屏实体投递，没有再次出现MapHost到Gate队列溢出。`1`到`4`几乎获得线性入场收益；继续升到`8/16`后收益递减，而广播pending和Location确认延迟持续放大。

正式Cold配置恢复并保持每Tick `1`人。下一步如需缩短Loading，优先用`4`做较长窗口、较少Gate和弱机器复测，再决定是否调整默认值。`8/16`保留为边界证据，不作为当前推荐配置。短测的正式窗口CPU采样不足，并且紧邻入场尾部，不能用于稳态容量结论。
