# OP-05 真实业务压测报告

日期：2026-08-19

## 口径

本轮使用 Starter 的真实 `UseItem` 与 `CastSkill` 请求，不伪造业务回执。业务规则拒绝单独统计，只有超时、断连、RPC 错配、协议解析失败才算传输错误。移动负载为每玩家 2Hz，Rust 容量组另加每玩家 0.2Hz `MapProbe`。

本轮没有启用 DBProxy 事务持久化，因此结果证明的是登录、进图、移动、AOI、技能/道具业务和状态同步的运行时余量，不代表商店、拾取、交易或跨玩家事务的数据库容量。

## Node 全链路 A/B

同一台机器、20 秒正式窗口、5 秒预热、50/100/200 玩家、all-in-one 与 split 各一轮：

| 部署 | 玩家 | 无业务 move/s | 无业务 move p95 | 业务 move/s | 业务 p95 | 业务/s | 成功/拒绝 | 传输错误 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| all | 50 | 100 | 50.09ms | 100 | 50.93ms | 5 | 100/0 | 0 |
| all | 100 | 200 | 61.51ms | 200 | 57.77ms | 10 | 200/1 | 0 |
| all | 200 | 400 | 63.10ms | 400 | 64.33ms | 21 | 382/46 | 0 |
| split | 50 | 100 | 50.09ms | 100 | 49.95ms | 6 | 110/5 | 0 |
| split | 100 | 200 | 54.01ms | 200 | 56.44ms | 10 | 200/0 | 0 |
| split | 200 | 400 | 61.32ms | 400 | 69.68ms | 21 | 377/38 | 0 |

200 玩家时 all-in-one Server CPU 峰值约 28.8%，split 各进程峰值合计约 84.6%，其中 Gate 是主要热点；两种部署均无 stalled、背压、Inner 超载或 Inner 超时。

Node 客户端继续放大到 600 玩家后，压测端调度明显落后，移动 p95 达到 3.48 秒并出现 12070 次跳过；1000 玩家 all-in-one 的内嵌 V8 达到约 1.3GB 后 OOM。因此 Node 全链路只能作为 SDK/协议链路验证，不能作为高人数服务端容量结论。

### 1000 玩家业务三轮复核

三轮中位数：Map CPU 47.4%，Gate最高进程平均/峰值 24.2%/33.3%，move 2000/s，Probe 200/s，Probe p95/p99 为 22.08/29.91ms；业务 100/s，成功/拒绝 1502/1498，业务传输错误 0，窗口背压、内部超载、内部超时和慢连接断开均为 0。

## 结论

按“移动目标达标、Probe 无错误、业务达到目标、传输错误/背压/内部超载/超时均为 0”的标准，本机当前 Starter 真实业务保守容量点为 **1000 个均匀分布玩家**。无业务可以稳定到 2000，但加入真实道具/技能后，2000 已出现队列和 Probe 尾延迟失稳。

这不是生产容量承诺：测试为单机 Windows IOCP、单 MapHost，且仍使用当前 AOI/下行模型。下一步应先定位 2000 玩家时 Map frame/completion 队列和 Gate 下行尾延迟，再复测 1500/2000；DBProxy 商店、拾取、交易和跨玩家事务需要独立的持久化业务压测。
