## 依赖与可复现目录

先完成 DBProxy、Developer Core、Native Core 的版本与独立检查，再本地提交/tag。宿主正式 Cargo/npm 声明全部指向这些候选 tag，移除 Developer 对 main 的浮动依赖。锁只由 Cargo/npm 生成，运行正式 codegen 与发行锁门禁；不得提交开发路径 patch、临时 tgz 或手写 lock。

尚未 push 的引用通过显式的本地 Git bundle/候选镜像交付。清洁构建命令临时将三个准确的上游 URL 重写到这些本地镜像，配置只属于该进程树；不改用户全局 Git/Cargo 设置。正式锁仍保留上游 URL 与真实提交身份。报告必须写清本地重现已通过，并指出远端安装要等后续获准推送依赖 tag，不能称未推送 tag 已可从 GitHub 下载。

冻结清单记录六仓库提交/tag、npm tarball/VSIX/Cindy/宿主包的 SHA256、实际安装文件哈希、锁和工具版本。清洁目录从 bundle 检出，npm ci/Cargo locked 使用正式声明，重复执行生成、检查、模块消费与制品启动，不复用开发树 node_modules 来冒充清洁验证。大体积编译缓存可以复用，但必须记录实际源码、依赖和最终二进制身份。

## 实际验收与停止条件

Host 驻留限额要求 Windows/Linux 真正 V8 与网络矩阵。插件使用实际安装的 VSIX；原生协议测试不能替代 Problems/Hover/Task。AI 客户端存在时使用隔离配置确认实际加载包与只读场景；缺少客户端明确列为未验证，不编造通过。房间、SLG、MMORPG 分别使用同一冻结宿主完成升级和运行；MMORPG 能力继续留在模块，位置服务保持可选。

性能先固定基线、构建参数、负载和容错门槛，再比较同机结果；编译/其他测试与测量阶段错开。长稳按 30、60、120、240、480、960、1440 分钟递增。每一级使用真实单次持续运行、保留请求/错误/延迟/资源/恢复证据；失败时保存证据、修复并重新验证受影响候选，从合适的较短级别重新开始，不能把多个短跑相加当作连续 24 小时。单轮连续 1440 分钟无问题后停止本机长稳；7×24 小时由用户另备环境。

发行准备包含候选包、校验和、升级/回退说明、已知限制、依赖发布顺序与本地提交。不得 push、远程发布、移动历史 tag 或把尚未完成的长稳填写为通过。
