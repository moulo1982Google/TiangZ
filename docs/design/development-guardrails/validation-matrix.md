| R05 no-op 身份 | 先 pending/指纹/业务回执契约 | 通用 AST 不承诺证明 | 受控 Store、真实回执 | 不强制所有 no-op 写库 |

## 2. T1 Model 正反例

| 用例 | 预期 |
| --- | --- |
| M01 原始值、冻结数组、普通/null 原型对象、允许的函数值 | 同真实运行期判定，passed |
| M02 导出冻结 Set、Map、Date、类实例 | failed，含模块/导出路径；冻结不改变非法形状 |
| M03 多级嵌套数组/对象里的非法值 | failed，报告实际嵌套路径 |
| M04 顶层 undefined、非法导出名称、symbol 属性、accessor | 原判定失败；getter 执行计数始终 0 |
| M05 循环与共享普通对象 | 正常结束；非法共享对象路径可复现 |
| M06 Component 实例字段有 Map/Set，但导出为构造函数 | passed；不错误禁用实例状态 |
| M07 两模块依赖、真实 Public API、漏/多/错版本模块登记 | 正例通过；错误预期图失败，不只数模块数量 |
| M08 与 bundler 的别名、声明宿主、模块依赖图一致 | 相同入口身份；非法深层导入失败 |
| M09 合法 Native worker 声明只被 Model 导出 | 形状通过；报告 nativeExecutionVerified=false |
| M10 顶层实际调用 Native / 未声明 op 或全局 | unavailable/failed；不提供虚假结果，不启动服务 |
| M11 子进程超时、超输出上限、中止 | 非 passed；确认自有进程树回收，后续 skipped |
| M12 两次检查与失败检查前后项目状态 | 源/锁/SDK/dist 字节及 mtime 不变；仅自有临时产物允许变化 |
| M13 IDE 静态实时检查、未信任工作区 | 不执行 Model 顶层；显式检查遵守信任边界 |

## 3. T2 协议与生成物

| 用例 | 预期 |
| --- | --- |
| P01 同模块两个不同 key 同一 code | 正式 check 失败，指出双方，不修改锁 |
| P02 不同模块同号 | 正式 ownership 检查失败 |
| P03 无文本冲突地合并两个协议分支 | 合并本身可成功，但最终 check 失败；修复后再正式检查 |
| P04 已发布编号、墓碑、Core 保留号 | 依现有政策拒绝非法变更，不自动重分配/回收 |
| P05 重复 key/条目、非法编号、合法空协议图 | 错误形状失败；合法空图清楚报告不适用 |
| P06 配置/协议/Native 生成物过期、缺失、被手改 | 指出文件与正式生成命令；原文件不被 check 修复 |
| P07 声明 SDK 同步目标而副本缺失/不同 | 游戏同步检查失败；未声明目标不得猜测路径 |
| P08 README 输入变化导致配置 fingerprint 过期 | 解释输入变化，重新生成后检查通过；本批不改哈希范围 |
| P09 两次合法 check | 锁、输出、mtime 不变；staging 自有目录回收 |

## 4. P0/P1 插件规则与分发

| 用例 | 预期 |
| --- | --- |
| A01 新增/既有规则集合 | 无重复同义 ID，权威文档/设计工具/技能对应 |
| A02 删除拟新增规则或破坏文档引用 | 包结构/同步检查明确失败 |
| A03 Codex/Claude/Cindy 打包 | 各维护源生成一致；不同入口能力范围明确，不复制大手册 |
| A04 写入本机路径、凭据、特定端口/吞吐值为通用规则 | 便携性/内容核对失败；特定值仅留案例或游戏 |
| A05 请求设计建议 | 相同输入结论确定；不声称读过未知工作区、运行检查或安装 |
| A06 分发源/包/锁版本不匹配，归档字节异常 | 分发/归档核对失败；不覆盖已装缓存 |
| A07 场景对话评估 | 逐项核对阅读/判断/命令/证据；记录真实可获得的模型身份，未知不补填 |
| A08 更新源但未生成、安装但未开启新会话 | 分别报告阶段；不声称行为已生效 |

AI 行为评估输入至少八类：非法冻结集合、合法实例集合、no-op+pending、重建历史回执、混合控制/数据 Scene、单玩家 ordered、跨端推算、未知 SDK/宿主身份。样例预期为语义约束，不用特定措辞匹配替代判断。

## 5. G1/G2 游戏兼容与故障

| 用例 | 预期 |
| --- | --- |
| G01 删除一个领域接入项、重复 record key、次序错误 | 类型/登记完整性或序列回归失败 |
| G02 原九领域快照、存档、回执、协议序列 | 改前后字节/版本/schema/错误次序相同 |
| G03 多领域成功与提交前拒绝 | 一次原子提交或完全不改；Apply/Push 按既有规则 |
| G04 数据库提交成功后回复丢失 | 同编号恢复结果，不重复扣/发，不改期望版本错误语义 |
| G05 结果未知后的同号/新号请求 | 原字节先恢复；确认后按当前状态规划；仍未知不记新成功 |
| G06 提交 A→B→重建→用旧 A 保存当前值 | 历史回执契约命中；不能由空计划直接 Remember |
| G07 新无变化请求、同号异内容、pending+无变化请求 | 原操作规则保持，不统一改成数据库写入 |
| G08 随机玩法结果未知 | 原随机结果与 detail 字节恢复，取随机次数不增加 |
| G09 await 期间对象销毁/客户端切换/新会话替换 | 已提交结果保留，旧对象不 Apply/Push，不串写新面板 |
| G10 同键并发、不同键交错、控制请求穿插 | 锁覆盖实际共有状态；同键正确，独立请求不被无关 DB await 阻塞 |
| G11 计时玩法停服跨截止重启 | 截止/状态恢复，领取只生效一次，不新增自动扣费 |
| G12 夹具的缺组件反例、状态隔离、真实 Model 加载 | 反例继续失败；用例之间无污染；真实加载校验不被桩绕过 |
| G13 真实服务端样本→真实客户端、目标构建/UI | 契约和实际表现都验证，Node/编译不能代填 UI |
| G14 提交后同步事件 | 保持现有数量/顺序；不宣称崩溃后持久投递 |

G04/G06 的真实 DB 回执证据不能只由假 Store 替代。实际数据库运行条件在那次试点任务开始时另核；没有运行则保持未验收。

## 6. 选测规则与结果口径

| 改动面 | 最低应选层级 | 另外触发的层级 |
| --- | --- | --- |
| 仅设计文档 | 链接、路径、状态与 diff | 无 codegen/产品测试 |
| 插件维护源 | 生成一致性、规则/引用反例、分发身份 | 实际 AI 场景单列；安装另按范围 |
| Model 导出工具/诊断 | 真实 Core 正反例、现有构建/类型路径 | 受影响真实消费方；Native 能力单列 |
| 协议/配置生成检查 | 既有生成器、合并反例、无改写、目标 SDK | 契约变更才需对应端运行；本计划默认不改协议 |
| 游戏领域装配 | 规则/假 Store/真实 Model、原字节回归 | 宿主、实际 DB 恢复；涉客户端再真实目标验证 |
| mailbox/事务/生命周期语义改变 | 原定向与受控交错验证 | 另出设计，不能由本计划自动扩大 |

失败必须记源/制品身份、阶段、首次命令和原错误；补验独立目录。定向运行核对实际用例集合，0 passed 不充当通过。所有必需步骤 passed 且自有进程回收后才关闭批次；unavailable/timeout/aborted/缺证据都留在遗留。

本设计不授权长稳、容量、性能、生产故障、清库、插件安装或模型 API 调用。后续任务明确授权的范围优先，命令存在不代表本轮可执行。
