# 0.7 已解码入站帧预算

2026-09-26 实施前冻结。N1 本步补齐 Rust Process 事件入口的共享字节额度，沿用现有队列、协议与错误路径，不增加游戏类型或路由特例。

## 配置与范围

`process.network.maxIngressBufferedBytes` 为可选整数，默认 67108864（64 MiB），范围 1..1073741824。旧配置继续使用默认值；新增字段同步 Rust、TS 和 Developer Tools JSON Schema，插件保留自己的版本序列。

Process 创建唯一额度，全部 TCP、WebSocket、io-uring 和 KCP 业务 listener 的已解码 `ProcessEvent::Frame` 共用；Inner RPC 控制帧与普通数据帧一起计入。计数为帧的逻辑 payload 字节，不含外层长度头、Rust 对象开销或 Bytes 底层保留容量，不称为精确物理内存。

入口在第一次尝试入队前无等待预留，既有 Bytes 转移所有权、不复制 payload。计数随最后一个 Bytes 引用释放，覆盖队列、等待帧数空位的发送 future、热更延后队列及出队后尚未打包的帧。重试入队不重复计费，取消、队列关闭、错误与正常交付都归还；不能在 dequeue 时提前归还。

解码器在此之前已分配单帧，此额度不覆盖半包/重组、打包到 Host 的另一份字节、V8/TS mailbox、RPC completion、KCP 可靠缓存或系统 Socket。这些仍是独立边界；同一数据的复制与释放位置必须说清楚。

## 拒绝与控制流

额度不足立即拒绝，不另设等待字节额度的队列。Inner RPC 复用现有目标入口过载响应（原 rpcId、原错误码），释放预算后同一连接可继续工作；普通外部/单向帧沿用接收失败后的连接或 Session 关闭路径，不能静默丢弃后谎报成功。

Disconnect、Shutdown 与 HostSceneCompletion 不占本项帧额度，继续走既有控制队列/帧数容量；这不承诺它们完全无背压或响应缓存无限可用。进程总量拒绝使用 `tiangz_transport_buffer_{bytes,limit_bytes,rejections_total}{kind="ingress"}`，与既有 `kind="outbound"` 同族、固定标签，不混作慢客户端或帧数队列满。

## 必须验证

- 控制/数据帧共享上限，超限不入队，释放后恢复；控制通知在字节满时仍可入队。
- 等待帧数空位不重复预留；取消、期限到期、接收端销毁及打包错误全部回收；热更延后持有到真实释放。
- 真实 listener 在满额度时关闭外部来源，Inner RPC 返回过载且同一连接恢复，其他 listener 的已接收帧不受损。
- 配置默认/边界/非法类型与固定标签指标；重建真实 Rust Host 后执行完整矩阵。Linux 条件编译与实际 I/O 验收分开记录。

本步不更新发布版本或 Stable 锁；正式冻结时由官方入口更新声明快照并重新做默认依赖/消费方验证。
