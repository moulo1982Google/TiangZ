# 0.7 调用期限资源所有权

基于本地 Scene 准入提交 `b533831`。当前本地 callFrame 的 Promise.race 无法取消 sleepHost：快速成功/拒绝仍占 TS pending 与 kind=3 宿主操作，直到原期限。Rust 把计时与远程 call/send 放进同一批 buffer_unordered(256)，后续期限甚至要等待前面的操作才开始计时。ProcessBootstrap.stopProcess 也有相同的竞速清理问题。

本批为本地 RPC 显式期限提供内部 withHostDeadline。期限资源由当前 V8 的 OpState/ResourceTable 拥有，Rust 记录创建时绝对 Instant，最多保留 65536 项，包含取消后异步等待尚未实际退出的资源。独立创建/等待/取消 op 不占远程 Scene 批次槽，不携带业务帧，不依赖普通 mailbox 准入或 Host completion 排队。沿用已有增量 V8 event loop pump；JS 业务长期不让出线程仍不能被此期限抢占。

先创建有界的原生期限与 TS 结果等待者，再执行业务调用；原生资源准入失败不启动目标。到宿主刷新时，只为尚未结束的调用启动原生异步 waiter，绝对期限始终取创建时刻。刷新前完成的调用在 finally 同步关闭资源，不创建原生异步操作；已有 waiter 的调用关闭后还需等待其实际退出。延后注册 waiter 若失败则拒绝等待，已经开始的目标仍归原 mailbox，不能假称没有执行。停机统一取消未启动/已启动的期限，释放原资源；不伪造目标业务取消。

超时保留原有 SceneCallFailed 文本与错误映射；过载仍按已知 1011/Rust 前缀映射。deadline 取消不取消业务；超时后的 callee、ordered 队列、Actor/Scene 名额和 Hotfix 排空继续依据真实业务完成。无显式本地期限的调用保持原路径，远程 RPC 仍由原传输期限负责。快速路径通过“没有创建 waiter”的确定性断言验证，不能靠提前清空真实计数或无限扩大额度换性能。

ResourceTable 只按期限资源类型关闭，未知或已经关闭的 id 幂等忽略；每个 isolate 的注册与预算独立，引用最终释放才归还预算。Core/宿主桥改变需完整构建重启，不增加 Model 在线替换入口。该内部能力不是游戏时间调度 API，不导出到 Stable Core；业务仍用 TimerSystem 的所有者回调。现有持久化退避 sleepHost、本轮之外的远程队列/字节/控制积压不在本契约中。

停机路径暂保留原语义：不能直接将“期限准入失败则不启动业务”的新包装器套到 runtime.stop，否则满额时可能跳过停机动作。停机控制需要独立定义保留额度或失败路径，本批不借清理期限改变该行为。

验证先保留公开调用提前完成后仍提交旧计时操作的 RED，再验证快速成功/拒绝、准入失败、取消确认、期限届满后的真实 mailbox 生命周期；Rust 验证创建时绝对期限、类型/重复关闭、实际引用归还、资源上限与不同 isolate。真实 V8 同时核对原生资源退出及生成协议的本地超时/热更恢复。最终执行含 KCP 完整矩阵与 Linux 条件编译，同步 AI 指引和实际分发；无新配置、Native schema 或编译规则，两个 VS Code 插件保持版本。
