# 0.7 远程 Host 操作的排队期限

本批基于 `76e64b5`，沿用前两批的共享准入和独立停机期限。旧探针 `temp/v0.7-remote-deadline-audit.json` 记录 20ms 的 call/send/sleep 在 TS 队列等 77.32ms 后仍提交 20ms；该探针不发网络。Rust 又在 `buffer_unordered(256)` 首次轮询每项时创建新的相对期限，所以后面的短操作会被前面的长操作推迟。本批冻结普通远程传输的时间所有权，再实现和验证。

## 单调时钟与批次边界

Host 提供不依赖墙钟的进程单调毫秒时钟。TS 在 HostSceneTransport 接受已编码帧时保存绝对到期时间；业务编码、业务 Handler 本身不在这个传输期限内。保留原 clamp、uint32 转换和 call/send 最少 1ms、sleep 最少 0ms 的含义，毫秒时钟向下取整，不能因浮点上取整延长期限。

保持既有 **4 字节批头、17 字节元数据、65536 项和 64 MiB** 二进制格式。flush 采样一次单调时间，各项只写剩余毫秒；此次采样值作为独立标量参数随 host submit 传递。Rust 使用相同的单调起点还原绝对期限，将 TS 打包、原生复制/解码和调度等待计入。标量不是用户配置或协议 payload；非法/未来采样明确拒绝，不回退墙钟或新起算时间。桥接改变需要完整重建重启，不能混用旧宿主和新 TS。

接受前的输入、回复名额、条数和字节检查保持。flush 先按既有规则隔离长度失效帧；已过期 call 明确失败，已过期 send 不再交给原生，正常到期 sleep 完成等待。未过期项保持相对顺序与原所有者，不能因本项过期丢掉其他接受项。TS 固定 Process 指标单独记录提交前 call/send 到期，不把 sleep 的正常到期或格式错误混为超时。

## 原生调度与实际工作

每批仍至多 256 个正在执行的 call/send。未开始项由有限的原批次槽和到期堆持有；slot 在调度或到期时转移一次，失效堆项被回收。最早到期的未开始项不必等前面的长调用完成：call 发失败完成通知、send 只记固定超时阶段而不投递，sleep 正常到期通知。sleep 不再竞争网络执行槽，不给每个排队项创建一个原生异步任务或无限重试。

实际 call/send 接收原绝对期限，连接队列/建连/写出/回复阶段不重新起算。等待 Host 结果也以原期限为界；停止等待不能撤回已写给对端的帧，物理传输仍保留原数据和最后引用，直到其自己终结。未获得执行槽的过期项不得晚到后继续开始业务，不自动重放事实。固定 `host_queue` 等超时阶段只描述发生位置，不能将多个阶段相加当作唯一业务请求数。

完成通知沿用现有有界控制通道与背压，不丢回复、不新建无界 completion 队列。TS 单线程被同步代码占用、运行时没有推进或控制通道拥塞时，观察到超时仍可能滞后；这不是严格实时响应保证。该回合不重设原生跨批次的总并发配额，不将任务数/单批大小外推为全部 V8/Rust 堆内存有界。

## 验证与修改范围

先补 TS 确定性反例：排队耗时扣除、提交前过期 call/send、sleep 到期、失效帧与其他项保留、原参数转换、共享容量及本地/停机期限独立。Rust 以实际调度器验证 256 个长操作占槽时后续短 call/send/sleep 到期、不会执行已过期项、完成通道背压下引用回收；再验证实际 V8 的标量时钟桥和真实生成 S 协议跨 Process 场景。完整含 KCP 矩阵、Linux 条件编译与 AI 实际归档另验，不把纯打包探针当成网络证据。

新的原生排队/到期职责集中在一个 `src/host` 子模块，已有桥接保留路由/格式/提交入口；这是独立调度职责，不按函数拆文件或增加仅转发层。两个 VS Code 插件没有新配置、Native schema 或编译规则需要调整；AI 三端需同步绝对时间、排队过期、完成通知及真实取消边界，继续保持独立版本。没有发布或用户服务改动。

## 反例与定向证据

TS 反例 **8 failed**，255ms，`temp/v0.7-remote-operation-deadlines-red.log`。修复后五文件 **43/43**，611ms，`temp/v0.7-remote-operation-deadlines-ts.log`；类型与双语注释检查通过。原共享准入、停机、本地期限和 legacy RPC 的关联号/完成断言保持，Native 替身补充了确定性单调时钟，没有放宽帧格式或容量。

真实 V8 RED `temp/v0.7-remote-operation-deadlines-native-red.log`：256 个 1000ms 普通 sleep 使后续短 RPC 超过 400ms 仍未完成，子进程失败。该用例没有网络管理器，短 RPC 本应立即失败或到期，不能把它叫作真实网络验收。修复后四项 Rust 专项 **4/4**，1.09 秒，`temp/v0.7-remote-operation-deadlines-rust.log`：除真实 V8 外，还覆盖 256 个执行槽已被可控结果占用时短 call/send/sleep 独立到期、未执行过期项、完成背压下保留后续槽/最后包引用，以及过去/非法/未来时钟校验。V8 子进程 watchdog 15 秒，调度用例总上限 3 秒；没有扩大反例阈值或减少并发。

TS 新指标为 `tiangz_host_scene_operations_queue_timeouts_total{process}`，只统计提交前 call/send 到期。原生沿用有界的远程传输诊断，在固定 `host_queue` / `host_wait` 阶段计数；阶段数不是唯一请求数。真实跨 Process 夹具复用正式 S 协议，主 Handler 等待已开始的 256 个 RPC 真正结束，不以脱离所有者的后台 Promise 掩盖热更排空。
