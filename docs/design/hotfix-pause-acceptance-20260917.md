# 2026-09-17：主动暂停与 Hotfix/config 联合加载验收

本文用于换机交接：记录实现边界、实际测试条件和下一步验收命令。实现说明见[热更设计](typescript-hot-reload.md)。只评价框架热更，不代表 SLG 业务已经完成。

## 实现约定

- 每个 Process 保持一套完整 Hotfix，不拆业务热更包，不引入新旧 generation 并行执行。
- 代码和完整 Luban 服务端配置组成同一个不可变候选，校验哈希、Model/协议/Native/schema/冷数据契约；配置单改也产生新发布身份。
- 独立线程先做制品验证和隔离 V8 预检，期间正常服务。准备完成后才暂停新业务入口，继续推进已接收业务、微任务和宿主完成通知。
- 暂停期间不新触发业务 Timer/固定帧 Update；时钟继续推进。排空后在原有两个 Update 之间同步提交代码和配置，不重建玩家、Scene 或连接。
- `process.lifecycle.hotfixReloadTimeoutMs` 默认 **3000ms**，最多预留100ms给同步提交。排空超时则放弃候选、恢复旧版本，不强杀 Promise。同步 V8 不能被此预算硬中断，不能承诺任何制品都严格在3秒内结束。
- 新的内部 RPC 请求也暂停投递，暂存上限128条，达到上限放弃热更；宿主完成通知继续处理。客户端携带 rpcId 不会成为内部控制消息，分类来自实际连接端点。
- 排队使用已有有界队列与背压，不是无限缓存。客户端超时不等于服务器取消；扣费、发奖等业务仍需幂等。跨进程依赖无法在窗口内排空时安全退出，不增加分布式任务追踪。
- 游戏业务禁止 await 时间；延迟用所有者 Timer 和方法名回调。数据库/RPC等结果等待仍允许。Model/Core/Rust变化、协议/schema/冷数据变化走完整发布和重启。

首次部署这些框架变化必须重新构建 Rust 与 Model 并重启 Process。之后才能在新宿主上使用上述热更能力。

主要代码入口：

- `src/process.rs`：后台候选准备、主动暂停、内部请求暂存、排空超时恢复和帧间提交。
- `app/core/process/ProcessRuntime.ts`、`ProcessBootstrap.ts`、`src/host.rs`：暂停模式下的时钟/队列推进与Rust/TS桥接。
- `src/hotfix.rs`、`app/core/hotReload/HotfixSystem.ts`：完整候选校验、代码/配置暂存、同步提交与失败恢复；构建端见 `tools/build_runtime_bundles.mjs`。
- `tests/unit/hotfix_drain.test.ts`、`tests/unit/atomic_release.test.ts`、`tools/hotfix_load_soak.mjs`：运行时单测、事务单测和真实负载；`tools/run_test_matrix.mjs` 将短负载纳入完整回归。

## 测试场景与证据口径

`tools/hotfix_load_soak.mjs` 通过正式脚手架创建临时模块，运行真实 Rust/V8 服务和生成的 TypeScript WebSocket SDK。Luban配置、协议与SDK都由正式生成器产生；测试不直接改生成物。

500个负载连接之外有一个控制连接。每个负载客户端目标每秒2次请求、最多一条在途请求，不是500名真实SLG玩家，也不是无界发包压垮服务的极限压测。

夹具在 await 结果前捕获代码版本，在等待后读取当前配置，把代码/配置组合与递增执行序号一起返回。断言仅出现配对组合11/22，执行序号不丢、不重复，RPC全部返回。代码或配置单边切换会产生非法组合。当前脚本还在每次更新后探测请求的配对确实生效，并校验回滚恢复前一配对。

故障注入包含：

1. 用另一条业务请求才能解除的真实未完成 Promise，令热更排空超时，检查旧generation保留，解除后恢复服务。不是在业务里 await 时间。
2. 损坏配对配置manifest，确认拒绝而不是加载半套。
3. 在持续负载中重复上述失败，再继续成功热更。
4. 最后整套回滚并验证业务序号连续。当前脚本还要求服务器正常退出，禁止把强杀清理算通过。

延迟分桶只统计负载RPC；发布/回滚探测也计入总请求、响应和序号。采样每30秒记录RSS、V8、队列与运维状态。两个候选交替切换，不等同于数百份不同内容的新制品测试。

一小时原始证据：`temp/hotfix-load-kDKkrs/report.json`、同目录`server.log`。报告status为passed，测试驱动退出0，末尾日志确认服务正常停止；早期驱动尚未单独记录serverExitCode。服务二进制SHA-256：`0e190debfde457ee5b4a68a3c6b517ed04b1862988107e7b841d89e1bc081983`。

一小时资源观察：第10分钟之后的定期样本RSS为191,074,304～200,359,936字节（约182.2～191.1MiB），最后回滚后即时值204,611,584字节；V8已用堆6,303,720～36,633,616字节，存在反复回收，V8总堆约61.4～63.7MiB。故障期间队列峰值500，最终队列0。RSS预热后仍有约8MB缓慢抬升，不能据此宣称“完全无泄漏”，需要高频切换与24小时曲线继续判断。驱动自身保留日志/采样会增长，应与服务进程内存分开看。

高频复测证据：`temp/hotfix-load-0xmgay/report.json`、同目录`server.log`；二进制SHA-256与一小时完全一致。第5分钟之后RSS定期样本192,770,048～203,665,408字节，最终回滚后204,521,472字节；V8已用堆5,868,408～33,559,912字节，最终总堆66,760,704字节，队列最终0。100次切换后的资源量级接近一小时6次切换，未发现明显按generation累积的膨胀；这不是24小时无泄漏证明。

**超时口径：**上述预跑和已启动的一小时进程加载的是脚本早期版本，继承通用SDK默认 **5000ms**。过程中补充的显式 `--rpc-timeout-ms` 不会改变已运行的进程。当前脚本默认显式 **30000ms**，不会修改通用SDK或游戏业务的超时配置。不能把5秒测试报告写成30秒测试。

预跑最初曾失败：第二个候选修改了Luban源数据却漏执行配置生成，报告发现240次混搭。已经补上正式配置生成，并在负载启动前断言两个候选实际配置值分别为1/2。没有放宽混搭断言；失败现场保留在 `temp/hotfix-load-s5pbuT/`，修复后的短测在 `temp/hotfix-load-T1Lr91/`，500客户端预跑在 `temp/hotfix-load-r0uy6P/`。

## 换机复测

先按主工程 README 准备 Node、Rust、Luban所需工具和依赖，检出同一套源代码。以下命令在 TiangZ **主工程仓库根目录**执行；Windows PowerShell 可用 `npm.cmd`，不用降低执行策略。

```powershell
# 包含codegen、TS/Rust检查和真实运行时测试；当前完整矩阵包含短负载测试
npm.cmd run verify

# 独立短测：20连接、15秒、每5秒切换
npm.cmd run test:hotfix-load

# 一小时，业务30秒RPC超时
node tools/hotfix_load_soak.mjs --seconds 3600 --clients 500 --reload-seconds 600 --requests-per-second 2 --rpc-timeout-ms 30000

# 更紧的5秒RPC预算；用于复现本次一小时测试的超时条件
node tools/hotfix_load_soak.mjs --seconds 3600 --clients 500 --reload-seconds 600 --requests-per-second 2 --rpc-timeout-ms 5000

# 10分钟内切换100次，观察反复预检与加载的资源表现
node tools/hotfix_load_soak.mjs --seconds 600 --clients 500 --reload-seconds 6 --requests-per-second 2 --rpc-timeout-ms 30000
```

脚本自动分配本地端口，使用独立临时工程与本地测试Token，不需要启动DBProxy，不连接现有线上服务；只停止自己启动的服务进程。结果保存在每次控制台打印的 `temp/hotfix-load-*/report.json` 和 `server.log`。最后一次计划切换提前约1秒，保证切换时仍有负载。

`temp/`、`dist/test-results/`不作为源码交接，需另行归档原始报告。本页汇总保留在仓库；迁移工作机不能只复制本页所列旧路径。当前报告记录二进制SHA-256、显式RPC超时、采样和退出码，可用于辨认实际受测程序。

```powershell

```

目标144次成功切换，加故障拒绝与最终回滚；请求数以实际报告为准，不以目标速率乘时间冒充实测值。期间避免并行构建、机器休眠或其他大负载；记录机器规格、二进制哈希及完整日志。

验收至少检查：脚本退出0且status为passed、请求响应与执行序号一致、RPC错误/混搭/重复为0、每次成功暂停小于3秒、注入失败保留旧generation、整套回滚正确、服务正常停止，以及预热后RSS/V8/队列是否出现持续增长。资源趋势需看完整曲线，不能用单次首尾值声称无泄漏。

当前场景不覆盖真实DBProxy慢IO/故障、经济业务副作用、跨Pod批量发布、Linux各网络后端的运行长稳、内部RPC风暴触发暂存上限及生产SLG容量。这些不是本次通过即可自动宣称完成的项目，应随业务接入再增加相应测试。
