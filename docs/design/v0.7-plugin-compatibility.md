## Native Language 已完成的具体证据

`npm run check`：Core/codegen 22 条、语言服务等扩展测试 7 条，共 29 条通过；`npm run package:extension` 通过。实际 ZIP 中 VSIX XML、package.json、构建身份及文件名均为 0.16.0；语言核心为 0.17.0，两个 bundle 哈希一致。候选 VSIX SHA-256 为 `0cdbd19b4feba0d0d8659481fafe88d5858a73e76841bd7a7a219163cc3a2ce6`。文件位于 Native 工作树 `dist/tiangz-native-language-0.16.0.vsix`，不是当前用户已安装版本。

复跑候选生成兼容检查：在 Native 工作树执行 `node tools/check-host-compatibility.mjs --engine ../TiangZ-0.7`。必须显式选择宿主，不按邻近目录推断。普通、persistent、queued、transactional 四个夹具共比较 21 份生成文本；新标记投影到旧语法后 Rust/Host op 内容保持相同。候选共 11 份 TS 生成文件通过宿主实际 TypeScript 6.0.3、严格选项和 Stable API 类型检查。

候选只写 Native 工作树的 `dist/host-compatibility`；CompilerHost 将夹具虚拟挂载到宿主 `app` 范围，保留宿主 rootDir，不改宿主 Generated、依赖或配置。该证据是生成文本/类型兼容，不代表已切换候选核心运行 Rust。

原失败也保留：首次对 import-only 包使用 CJS `require.resolve` 被 exports 拒绝，改为读取宿主实际安装清单的 import 入口；随后跨仓库夹具落在宿主 rootDir 外触发 TS6059，最终以虚拟文件挂载解决，没有屏蔽诊断或放宽类型规则。日志依次为 Native 工作树 `v0.7-host-compatibility.log`、`v0.7-host-compatibility-checked.log`、`v0.7-host-compatibility-final.log`、`v0.7-host-compatibility-virtual.log`，最终报告在 `dist/host-compatibility/*/report.json`。

- `businessTimeDiagnostics` 已在 Developer Tools `project-core`，编辑器工程分析和宿主模块检查复用该函数。
- 主工程的部分 Hotfix/lifecycle 检查仍在 Developer Tools `projectAnalyzer.ts`；独立模块工程默认委托声明的宿主，不能套用主工程扫描布局。
- 宿主 `hotfix_class_rules.mjs` 配合 `core_type_symbols.mjs` 使用当前宿主声明身份，覆盖导入别名和 namespace；它仍是宿主源码中的另一入口，不能宣称已经全部共享。
