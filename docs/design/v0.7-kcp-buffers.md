# 0.7 KCP 可靠缓存预算

2026-09-26 实施前冻结。前两项预算不覆盖 `ikcp_send/input` 复制到 C 的数据，也不覆盖未确认重传和输出回调副本。本步以现有固定版本 C 源码为依据，保持可靠消息语义和 Session 隔离。

## 所有权和上限

新增 `process.network.maxKcpBufferedBytes`，可选整数 1..1073741824，默认 67108864；全部业务 KCP listener 共享。每个 Session 另有 4 MiB 上限，不排队等待额度。客户端库未加入 Process 时使用独立预算，不能声称与服务器共享。

此额度保守计入 C 控制块、MTU 工作缓冲、发送/接收 queue/buffer 段、保留的 ACK 数组容量以及尚未释放的输出 Bytes。段按 `sizeof(IKCPSEG)+mss` 计上界，非精确 RSS；输入拒绝超过协定 MSS 的段，不能让估计小于 C 实际分配。配置与 MTU 初始化、ACK 数组扩容还须预留旧/新分配同时存活的峰值。

通过自有 C shim 读取计数并计算 O(1) 上界，不修改第三方 C 源码或替换进程全局分配器。send/input 在进入可能分配的 C 调用前预留保守增长，返回后缩减到实际结构的上界；ACK-only 包在额度满时仍可进入并释放已确认数据。包含 PUSH 的复合包按最坏增长预留，不承诺在临界额度下先处理其中 ACK 再接收数据。

输出回调在复制前预留两级额度，返回 Bytes 持有守卫，pop 不提前释放。C flush 不依赖 callback 的负返回值停止：一旦回调拒绝或 panic，包装器必须记录终止状态，update 返回错误；业务端关闭该 Session，不能默默丢包后继续声称可靠。C 发送失败同样终结该业务 Session，修正现有只记 warn 的路径。

## 范围和兼容

不计 Rust 容器容量、allocator 元数据、解码/receive 返回副本、UDP 封包副本、系统 Socket 或 TS/V8 内存；这些不因 KCP 限额而变成全进程内存上限。KCP payload/片数仍服从固定 C 实现原有限制，不把通用 1 MiB 帧上限当成 KCP 一定支持的消息大小。

服务器创建 Session 失败只拒绝该连接；周期 update/input/发送超限只回收已确认归属的 Session，不能退出整个共享 listener。固定 `kind="kcp"` 指标反映共享占用、上限、共享额度拒绝；单 Session 限额失败单独明确日志原因，不混作共享额度或慢客户端。

Rust KCP 包装器 `update` 改为返回 Result，`take_output` 返回持有预算的 Bytes；更新全部实际调用方与测试，作为 0.7 源码兼容变化记录。线上的握手/消息格式不改，默认额外限额需部署方容量验证。Developer Tools/AI 同步实际范围，版本不与框架统一。

## 验证

至少包括：跨 Session 共享拒绝与释放；未确认发送持续持有、纯 ACK 满额度仍可归还；接收乱序/ACK 数组扩容及异常报文；输出 pop 后最后引用/克隆释放；输出回调失败必须显式终止；已有消息边界/丢包重传；真实 listener 只关闭过限 Session 并保持其他连接可用；配置与固定标签；Windows Rust/Clippy、Linux 条件编译和重建宿主后的完整矩阵。
