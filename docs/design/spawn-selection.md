# Spawn Selection 运行时

`SpawnSelectionComponent` 是 MMORPG 层的通用“候选刷点选择”能力。它不知道 WoW、ACDB、
来源表名、地图编号或怪物种类；外置游戏模块只登记冻结后的中立候选组。

## 内容契约

每个 `SpawnSelectionGroup` 声明稳定组 ID、`maximumActive`、可选的 `initialActive` 和候选。实体候选形状为
`{ kind, spawnId, weight }`，可引用 Monster 或 Interactable；组候选形状为
`{ kind: Group, groupId, weight }`，用于建立严格的父子层级。

同一组内不同实体种类共享一个容量。被引用的实体刷点必须存在于同一地图内容目录，并设置
`initialSpawn=false`。目录在地图发布前原子登记并封存；重复实体、缺失子组、一个子组拥有多个父组、
自引用、循环、非法权重和超容量都会使启动失败。`initialActive=false` 只允许根组声明；子组的生命周期始终
由直接父组拥有，不能同时接受外部启停。

## 生命周期

1. 地图启动时只填充 `initialActive!==false` 的根组；每组按相对权重无放回选择至容量上限。选择组候选时递归填充其子组。
2. 活动实体进入重生冷却时，候选槽在 `eligibleAtMs` 前仍占用容量，不会提前用其他空槽补位。
3. 根组实体到期时，只重抽该实体对应的一个槽。若实体属于子组，则到期触发的是直接父组中的子组槽，
   而不是跨越层级修改祖先组。
4. 若重抽仍选中原候选，先停用原候选（组候选会停用整个子树），再完整激活；若选中其他候选，先激活
   新候选，再停用原候选。这样不会把旧子组中仍存活的实体遗留在地图上。
5. 重复释放是幂等的；定时器只推进中立状态机，不包含来源游戏的协议、编号或概率解释。
6. 外置模块可通过 `ActivateGroup/DeactivateGroup` 幂等启停由它拥有的休眠根组；激活时重新抽取候选，停用时完整
   清理根组子树。缺失组或对子组直接操作会立即失败，避免活动所有权与父组所有权重叠。

`SpawnSelectionRuntimeState` 接受可注入随机源。自动测试覆盖加权启动、共享容量、每个冷却触发只替换一个槽、
层级切换时完整停用旧子树和循环拒绝。选择状态默认属于地图进程；需要持久化选择的游戏由其模块另行定义
策略，不能把某个游戏数据库的持久化语义塞进此组件。

## 模块边界

- TiangZ Model：定义候选组、层级约束、内容 profile 和组件契约。
- TiangZ Hotfix：验证实体目录，执行选择、冷却、激活和停用。
- 游戏模块：把自己的数据表、概率和活动规则转换为中立组。
- 协议适配器：只观察实体 AOI 与业务事务，不参与选点。

新增区域因此可以通过内容生成完成，不需要为每张地图修改 TiangZ Core，也不会把某个游戏的 Pool 编号、
日历或脚本规则固化成框架能力。
