# 0.7 可观测性纯拆分

## 健康入口与指标格式

`src/health.rs` 保留健康状态、快照类型、HTTP/管理入口和 HealthServer 生命周期；`src/health/metrics.rs` 集中保存 Prometheus 格式化，包括标签、指标种类和 histogram。子模块读取父模块已有私有状态，不暴露字段；仅格式化入口对父模块可见，没有新增转发类或分散成逐指标文件。原有 15 个健康/指标测试保留在父模块，通过既有调用入口验证。

以 `dbcd1c9` 为基线，移动 13 个函数。除入口的 `pub(super)` 可见性及模块 import 外，全部声明文本（含执行体、字符串、标签、名称、顺序）机械比对相同；rustfmt 后再次通过，规范化 SHA256 为 `a1ac553fbda1f7b18e7ae8255f4be10d06cd1e7d151f2788d2c669c121e77b8c`。证据为 `temp/v0.7-health-metrics-move-final.json` 与 `temp/v0.7-health-split-tests.log`（15/15）。完整矩阵在后续 Process 采样拆分后合并运行。

这属于 Rust 物理组织调整，不改变指标契约，不需要协议/配置 codegen；实际二进制仍需重建并重启 Process。纯搬移与行为变更分开提交。

## Process 采样与快照转换

`src/process/observability.rs` 保存 8 个内部指标 DTO/枚举及完整采样/快照转换函数。Process 调度、入站队列、V8 GC callback 和裸指针所引用对象的生命周期仍留在 `process.rs`。父模块仅导入四个 DTO 类型和采样入口，字段可见性没有扩大；两个直接检查 DTO 字段的原解析测试随其类型移动，其余 Process 测试保留。

以 `c424667` 为基线，8 个类型、1 个函数、2 个测试的规范化文本均相同（只消除必要的 `pub(super)` 差异）。类型 SHA256 为 `1a4b8e4707802e088632710f47ee7538bef273e283b354d6039eb9d54b0c4c2d`，采样函数为 `237fa91f09c3f2b7bf82d4a23a6ba56aaa8c13da057750041a536229134d2d6a`；证据 `temp/v0.7-process-observability-move-final.json`。

首轮完整 Rust 联跑出现一次原生退出 `0xc0000409`（`temp/v0.7-process-observability-tests.log`），没有可用原生栈，不能记为通过或归因为机械搬移。随后同一二进制保留并发的诊断轮、6 轮 nocapture、4 轮原捕获模式，以及本机 CDB 调试器下各 161 条全部通过；日志 `temp/v0.7-process-observability-native-diagnostic.log`、`v0.7-native-diagnostic-round-*.log`、`v0.7-native-captured-round-*.log`、`v0.7-native-cdb.log`。重复通过不等于已定位该次异常，保留为待定位现象。检查同时发现新增 N3 用例在同一 OS 进程不同线程重复运行 Process，与 deno_core 对 V8 初始化父线程的要求存在测试拓扑风险；后续隔离夹具另行提交，不能作为该原生异常的已证实修复。
