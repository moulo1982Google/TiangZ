# 0.7 Model / Hotfix / Stable 依赖方向

共享 AST 规则归 Developer Tools `dependencyRules.ts`，独立 dependency ruleset 1，不更改生命周期/Hotfix ruleset 2 的含义。主工程 CLI/实际 LSP、宿主 `verify:domain-boundaries` / `verify:hotfix-boundary` 和模块 CLI/只读 Host worker 调用同一规则。宿主保留模块清单、直接依赖和版本验证，生成锁/指纹仍是额外检查，不复制到插件。插件仍为 0.15.2。

检查静态 import/export、字面量动态 import、import-type、import-equals 及相对类型增补；注释/普通字符串不当依赖。动态表达式给明确 warning，任意反射、业务 require 包装器不属于完整证明。Program 提供实际导入目标，路径别名不得掩盖层级或把 Stable 入口指向另一个宿主/内部文件。主工程 Program 结果替代同文件的纯文本检查，避免重复诊断；类型环境不可用仍显示原有不可用状态及可确定的语法诊断。

Model 业务仅使用 Core public 入口。保留精确的 `app/model/main.ts`、`app/model/public.ts` 与既有 bench bootstrap 例外及 Generated 三层原方向，不泛化目录白名单。模块使用清单的 Model/Hotfix roots；`#tiangz/modules/*` 必须经宿主公共 API resolver 证明直接依赖。生成协议内部 ABI 仅限 serverOutput、正式生成器标记和四个精确 ABI 文件；System.d.ts 的领域原声明例外同时检查路径与生成器标记。这些标记不是安全认证，不能代替生成完整性检查。

首轮 Developer Tools `dist/v0.7-dependency-rules-first.log` 为 5 项中 4 项失败：Model 深入 Core、Core 使用 Model 别名、type-only/import-equals、相似启动文件。旧正例曾允许 Model 深入 Core，已按现行 AGENTS 改为 Stable public，新增反例继续保持错误预期；不是放宽生产规则。旧 LSP 夹具把 `#tiangz/model` 直接映射 Core，现补真实 Model 聚合文件，并通过新增深层导入诊断验证 CLI/LSP 的错误及未保存修正一致。

需完成纯规则/TS 5/6 对照、当前宿主与模块正反例、实际 VSIX 安装后 LSP、候选 npm 制品字节身份和 AI 归档，以及宿主 quick 矩阵。本文件后续追加实际结果；不能把前一批生命周期 full 通过当作本批规则验证。
