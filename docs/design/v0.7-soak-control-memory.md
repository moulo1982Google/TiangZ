# 长稳控制进程内存与完整报告

本项只修改验收工具，不修改 TiangZ/DBProxy 业务、协议、Rust ELF、PG/AOF 2 秒或 SDK 5 秒预算。故障长稳必须同时观察被测服务和测试控制进程；客户端负载完成不代替空载观察、独立对账与真实退出。

## 已确认的缺口

2026-10-03 21:22:37，diagr3 完整 960m 的负载、80 次故障恢复和客户端终态已完成，但在发布空载开始报告期间，512MiB 客户端父 cgroup OOM 杀死 Node 驱动。300s 空载和独立 SQL/Stream 对账未完成，因此该轮资格为零；既有独立通过的 480m 保留。

在同一父组内另起短诊断进程，实际云端 Node v24.18.0 的 `heap_size_limit` 为 **2348810240 字节（2240MiB）**，`process.constrainedMemory()` 返回近似无限值。直接 service 无限额、祖先 slice 为 512MiB 时，默认堆预算没有识别该祖先预算。它是已实测的配置缺口；旧驱动进程已退出，没有失败前堆快照，不能由此断言全部 505MiB RSS 的具体保留对象或某个 Node/libuv 缺陷。

Windows 单独重建旧报告约 27MiB、峰值约 168MiB，也不足以重现原 16h 进程的网络、轮询、分配与 GC 历史。原驱动同时把全部 progress/samples/intervals 常驻内存，并整份 stringify，存在随测试时长增长的明确保留路径。

## 修复契约

- Node 驱动显式设置 old space 128MiB、broker 64MiB、独立复核 192MiB，semi space 均为 4MiB。实测对应驱动总堆上限约 140MiB、复核约 204MiB。堆额度不是 RSS 或整个共享组额度；原父组 512MiB/禁 swap/50% CPU 保持。[Node CLI 参数](https://nodejs.org/download/release/v24.20.0/docs/api/cli.html#--max-old-space-sizesize-in-mib)。
- `tools/lib/soak_report_history.mjs` 的 ReportHistory 独占创建 JSONL，逐条保存完整记录，内存只留末条和计数。报告保留原完整数组与两空格 JSON 格式，逐条解析、编码；不裁采样、不丢门禁行，不改变故障分类。
- `soak_control_io.mjs` 的分块发布支持短写，写完同步并关闭后同目录原子 rename。Windows 原 1 秒共享冲突重试不改变；来源、磁盘或发布失败保留旧报告和未发布候选，不得改成 passed。旧小文件发布接口保持。
- `soak_control_memory.mjs` 读取真实 cgroup 祖先的最小有限限额，保存 heap/external/arrayBuffers/RSS/进程峰值，以及共享组 total/peak/stat/events/swap。默认大堆、观测缺失、进程 RSS、组 OOM/swap 或预留超限均拒绝；不触发强制 GC。
- 干净文件缓存保留在总量证据里，不直接当成匿名内存泄漏。总量仍受原 512MiB 限额；64MiB 预留检查使用 `anon + kernel + shmem + file_dirty + file_writeback` 的保守合计，不能称为内核精确工作集。各分项必须完整，不能将缺失补零。[cgroup v2 字段定义](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files)。
- 新云端驱动每 5 秒与采样/报告边界记录控制内存，Python 同时记录协调器、broker、驱动的真实 PID/启动代次/RSS。进程恰好退出时记录未知内存和 Popen 实际退出码；活进程缺 RSS 或身份改变仍失败，不能制造零值。
- 大制品哈希改为 1MiB 分块；资源趋势只保留所需的时间/RSS标量，完整原始采样仍在文件与最终报告中。独立复核增加控制内存完整性与预算检查；原客户端、故障、AOF、SQL/Stream、空载和退出门禁继续执行。
