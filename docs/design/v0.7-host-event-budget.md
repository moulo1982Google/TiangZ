# 0.7 Host 事件驻留预算

2026-09-27，夜间工作授权下落实的候选契约。这里只界定框架拥有的二进制存储与预留，不把业务对象图、业务复制、V8 总堆或 RSS 称为有界。

## 准入与所有者

- 每 Process 的数据帧、远程 call/sleep 完成共享 512 MiB 驻留额度。每项成本为 payload 字节数 + 128 字节；其中包含 13 字节事件头与保守分摊的批头，余量降低小消息保留大量守卫的风险，并非精确分配器开销。
- 入站帧在进入 Native 队列前预留实际长度；Rust 原帧仍由独立 ingress budget 计费。RPC 满额沿用执行前 1011，外部/单向消息关闭原来源。
- Native 提交批次时，call 按传输既有最大响应 1 MiB 预留，sleep 按空 payload 预留，send 不产生完成事件。全批成功预留才 spawn；任一失败释放本批并返回既有 `[scene-overloaded]`，任何操作尚未执行。512 MiB 最多同时容纳 511 个尚未获得实际长度的最大响应预留；小回复确定长度后马上缩减，不永久按 1 MiB 计费。
- 已完成结果缩减到实际 payload 成本后，沿 completion、Host packed Vec、V8 backing store 转移同一守卫。成功结果不能再因额度不足被拒绝。错误文本限制为 4096 UTF-8 字节并明确标记截断；不修改成功业务 payload。
- Disconnect 独立预留 65536 项 backing-store 所有权，每项保守计 128 字节（总 8 MiB）；不与数据/回复竞争。与既有未开始控制数量是两个释放点：数量在 TS 开始时释放，backing 直到最后引用释放。满额等待留在原连接清理任务，沿用原截止时间，接收器退出唤醒；Shutdown 和专用停机期限不占该额度。

## 混合批次与峰值

保留现有批次格式、混合顺序及取队公平性。每个事件守卫移动进 batch，随安全 Box 容器交给 V8；小 subarray 保留整块时，也保留整批守卫。不能保留原 Bytes 来假装守卫转移，不能在 EntryScene Promise 完成时释放，因为 Actor DTO 可能仍引用 bytes 字段。

驻留额度是尚未兑现的回复预留、Native 完成 payload 与 V8 backing store 的保守和。原帧的 ingress 配额独立；Host 正在打包时存在一份至多 64 MiB 的 payload 复制，Vec 扩容/缩为 Box 的临时重分配另至多一个批次。不得将 512 MiB 称为整个进程峰值。网络解码器、Socket/OS 缓冲、其他 op、任意业务堆与分配器开销另计。

GC 未回收的存储继续占用额度，即使业务已置空。满额只拒绝新增业务，不强制 GC、不创建无限等待队列、不重放已执行事实。业务持续持有旧回复并等待新 RPC 时，新批次立即过载；已接受的回复有预留，可以继续交付。正常自然 GC 或 isolate/最后 Native 引用销毁后恢复额度，不能保证 GC 的实时性。
