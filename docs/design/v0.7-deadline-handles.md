# 0.7 原生期限句柄的长期使用

本批基于 `dcd5dd8`。当前本地/停机 Deadline 每次都加入 deno_core 0.411.0 的 `ResourceTable`；该依赖的 `io/resource_table.rs` 使用 `u32 next_rid` 单调递增，`take` 只移除条目，不回收编号。原来的存活额度和最后引用测试证明了资源释放，但没有证明编号不会被高频调用消耗。

在既有真实 V8 生命周期用例末尾增加独立通用资源编号断言，得到 RED：`temp/v0.7-deadline-handles-red.log`，子进程 2.43 秒、父进程 2.48 秒，**1 failed**。所有期限已经归还、通用资源表只有原来一项时，下一个通用编号仍从预期 1 变成 **131080**。这证明 131079 次成功期限创建消耗通用编号，不是内存泄漏证据，也没有实际执行四十多亿次创建或复现生产溢出。不能通过重置整个通用表、覆盖依赖私有字段、扩大存活额度或定期重启来伪装修复。

## 冻结的内部契约

期限由 isolate 的 OpState 内一张专属表持有，继续使用既有 `Deadline`、绝对 Instant、CancelHandle、单 waiter 和最后引用归还。普通 65536 项与停机 1 项的原预算保持，不新建第二套 Timer，不改变业务取消语义。创建失败不留下条目或占用，不让普通编号耗尽阻塞停机自己的编号空间。

内部句柄为 JavaScript 可精确表达的安全整数：普通使用递增偶数，停机使用递增奇数，两者各有计数器，均不复用本 isolate 已发出的编号。Rust 以 u64 保存，桥接传递安全整数 Number；不经过 u32 截断。上限为 `Number.MAX_SAFE_INTEGER`，超出时明确按过载拒绝本次创建，保留已有条目与另一类编号，不回绕或将相邻句柄四舍五入。未知或重复关闭幂等忽略，等待未知句柄明确失败；负数、非整数、非有限值和超出安全范围在 JS 与直接 Native op 两侧拒绝。

句柄只属于当前 isolate，不持久化、不导出 Stable API，不向其他 Runtime 转交。关闭从专属表移除并请求取消；已开始的 waiter 仍持有原资源直到真正退出。OpState 清理时专属表请求取消全部所持期限，再释放表引用；外部仍存活的原等待引用不能提前归还额度，也不能影响新 isolate。通用 Deno 资源表的编号与其他资源不被触碰。桥接变更需完整构建和重启。

## 验证与边界

保留原真实 V8 的 65536 满额、256 个在等资源、停机预留、重复取消和 65540 次实际等待/关闭，新增通用编号不前进断言。专属表以可控边界种子验证大于 uint32、最后安全编号、明确耗尽、两类互不干扰、旧句柄隔离、取消后最后引用和表析构；实际 V8 验证桥接与直接 op 的非法数值、超过 uint32 的句柄和 Runtime 清理。

相关 TS/原生回归后重建 Host、完整含 KCP 矩阵、Linux 条件编译及 AI 实际归档。内部 op 没有用户配置、Native schema 或新编译规则，两个 VS Code 插件无需跟随改版；AI 指引补充句柄/所有者与编号耗尽边界。复测命令 `node tools/run_cargo.mjs test --bin TiangZ --features kcp host::deadlines::tests -- --nocapture`。有限边界测试不外推为整机长稳，也不代表其他 Deno 使用方不存在编号消耗问题。

## 定向验证

Rust 专项 **9/9**，2.51 秒，编译 13.01 秒，`temp/v0.7-deadline-handles-rust.log`。原真实 V8 的 131079 次成功创建/回收后，下一个通用编号保持 1；普通满额和独立停机预留的原断言保持。实际桥接接受大于 uint32 和最后安全整数，JS 包装与直接 op 均拒绝非法值；未知等待、重复关闭和编号耗尽正常，Runtime 清理后的残余 waiter 真实退出才归零。新增表测试覆盖旧句柄隔离、两类耗尽互不影响、拒绝原子回滚及析构不提前归还。

测试编译失败 `temp/v0.7-deadline-handles-compile-failure.log` 保留：op2 宏入口生成 OpDecl，不能直接当普通 Rust 函数调用（E0061/E0599）；Drop 类型不能用结构更新语法搬出非 Copy 字段（E0509）。已改为实际 V8 调桥创建资源、边界测试显式初始化；没有删掉 Drop 或原断言，两份 AI 开发入口同步教训。完整矩阵和 Linux/制品验证另行记录。

相关 TS 五文件 **43/43**，599ms，`temp/v0.7-deadline-handles-ts.log`；全目标含 KCP Clippy `-D warnings` 通过，4.42 秒，`temp/v0.7-deadline-handles-clippy.log`。没有改业务 TS、取消语义、容量或故障测试阈值。
