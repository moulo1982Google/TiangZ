# 外置模块实时检查接线

2026-09-26 实施前冻结：模块仍由其声明的 TiangZ 宿主发现、绑定 Core/模块公开入口/生成 System 声明和检查依赖边界。编辑器不猜测另一个 tsconfig 的宿主，不在插件中复制模块目录发现或 Hotfix 判断。先将已有宿主检查从 CLI 中提取成可调用单元并保持诊断，再为实时请求增加未保存 TypeScript 文本与可复用 Program。

模块工程仅在 VS Code 已受信任时启动所选宿主的只读诊断 worker。worker 使用宿主自己的 TypeScript 与已安装共享规则包，和 CLI 调用同一检查入口；不运行生成器、Cargo、业务模块或构建，不修改协议锁/磁盘源码。宿主路径只读取已保存的 tiangz.project.json；未保存项目/模块声明和 tsconfig 需要明确提示保存后重新装载，不能据编辑缓冲区启动另一个宿主。

普通未保存 TS 内容在内存中覆盖当前模块集合内的源码，关闭文档恢复磁盘内容。未知或越界文件拒绝覆盖，不允许借 overlay 替换宿主工具或其他 checkout 的 Core。声明、依赖或宿主发生变更时清空原检查状态并重新建立环境；宿主不支持该能力、依赖缺失或类型环境失败必须显示不可用，不能伪装成零错误。

每个活跃模块工程只保留一个 worker，请求去抖、同一时刻一个在途检查，更新合并为最新文本；旧结果不能覆盖较新的文档版本。工程关闭、取消信任和服务器 shutdown 释放 worker 与诊断。最多四个工程 worker；每个类型缓存延续 10000 文件/128 MiB 源文本上限，协议帧/等待时间另行有界。缓存源文本限额不冒称整个 TS 进程内存上限。

当前容量选择：单工程最多 16 个模块 Program；未保存源码最多 256 个、单文件 2 MiB，单条请求/回复 16 MiB，启动和单次检查各限 30 秒。额外工程显示不可用，关闭工程后刷新可释放名额，避免反复逐出导致重新编译。依赖安装或宿主工具升级后刷新检查环境；实时 worker 不自行安装依赖或生成声明。

验收先对提取前后 CLI 诊断做回归，再用同一工程验证 CLI/实际语言服务器的确定错误、warning、未保存修正和关闭后回收；包含当前/旧宿主混用、生成方法、依赖错误、损坏声明、不受信任/信任撤销、过期回复及 worker 退出。实时覆盖完成前保留现有“模块仍通过宿主任务检查”的文档事实，不提前声明完成。

## 实现与验收记录

宿主检查已纯提取至 `tools/module_typecheck.mjs`（`7f5ac00`），与提取前函数体规范化哈希一致。worker 和 CLI 调用同一入口，Program 缓存按模块隔离 AST，保留旧 Program 和未变文本，关闭或失效清空。规则执行顺序仍与 CLI 相同：类型错误、共享契约、业务时间、运行时桥、Hotfix 类形状；不是整个 check/build 流程，不宣称所有依赖方向规则已统一。

Developer Tools 把进程协议集中在 `extension/src/moduleLiveChecks.ts`，LSP 保留索引和发布责任。只有明确受信任通知才启动 worker；失效版本在收到编辑时立即标记，非等去抖结束才标记。手动刷新重建 worker，已有关闭进程退出后才能重新占名额。源码范围/声明文件由宿主 ready 消息给出，支持模块联接及真实路径编辑；项目声明的宿主路径不从 overlay 读取。标准源目录与自定义目录的磁盘 TS 变动均触发重查。

已通过宿主 4 项 cache/worker 测试与真实语言服务器对照：同一 TS 6 工程的 CLI 诊断、动态 warning、未保存修正、缺失导入和关闭恢复一致；真实路径位于另一盘的模块通过目录联接安装，Problems 仍定位真实源码。父进程 IPC 夹具另验信任门槛、过期结果、只合并最新编辑、四工程限额、worker 退出/格式错误/16 MiB 超限及 shutdown 回收。测试夹具和编译器验收分开报告，未声称 VS Code UI 人工交互或长稳完成。

失败教训：扩展原位置转换用 `path.join(root, ...relative.split('/'))`，跨盘 `path.relative` 返回绝对路径时会被错误拼接；改为 `path.resolve` 并断言实际 publishDiagnostics URI。真实路径模块不能只按工程根过滤打开文档，须由宿主返回目录和声明集合筛选。首次新增 IPC 测试误把 Map 首个进程当目标工程、缺失导入使用默认未启用检查的 side-effect 形式；修正为观测实际退出状态及具名类型导入，未改生产诊断条件。脚手架另一次正确拒绝覆盖 mkdtemp 已创建目录，最终在该私有目录下创建未存在子目录，不绕过拒绝覆盖。原失败日志 `dist/v0.7-module-live-lsp-second.log`、`dist/v0.7-module-live-lsp-linked.log` 保留。

复测入口：宿主 `node --test tools/module_type_cache.test.mjs tools/module_live_worker.test.mjs`、`node tools/module_typecheck_host_self_test.mjs`；插件设置 `TIANGZ_TEST_MODULE_HOST` 后 `npm run check`，实际安装版本可再设置 `TIANGZ_TEST_SERVER_PATH`。未指定宿主时真实联合用例明确 skip。后续包身份与安装结果记在[插件兼容记录](v0.7-plugin-compatibility.md)，不以源码检查代替已安装制品。

最终宿主 `temp/v0.7-module-live-verify-quick.log`：quick **33/33**（内部 check **8/8**），包含新增 4 项 worker/cache 测试及原宿主身份/System 声明检查。Developer Tools `dist/v0.7-module-live-check-complete.log`：**138 项通过**（Core 69、design 6、design-cli 3、design-mcp 1、CLI 10、server 49），真实 Host 用例没有 skip。实际安装服务另跑 **11 项通过**，日志 `dist/v0.7-module-live-installed-lsp.log`；随后新增在途撤销信任/四工程刷新后的进程释放断言 **2 项通过**，`dist/v0.7-module-live-installed-cancel-refresh.log`。
