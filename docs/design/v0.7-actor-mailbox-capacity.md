# 0.7 Actor mailbox 准入容量

本批基于 `f2f8498`，冻结任务数量与拒绝传播契约，不在同一提交搬移 mailbox 实现或承诺 V8 堆字节上限。

每个 Actor 最多接受 **4096** 项排队加实际运行的调用；原 ProcessHost 合计最多 **16384** 项。单 Actor 采用已有 unordered EntryScene 的 4096 并发量级，Process 允许四个这样的满额所有者，防止不断创建 Actor 绕过局部限制；这是候选运行时的固定防护界限，不是吞吐/RSS 定容结论，也不新增可设成无限的配置。先检查 Actor 再检查 Process，同一次拒绝只归入一个计数。RPC、void 单向、ordered/unordered 和 Timer 进入 Actor mailbox 时统一检查；拒绝在入队或业务执行前同步抛出 RpcError(SceneOverloaded=1011)。原 Actor 不存在的错误契约保持。

计数覆盖已入队和已开始任务。销毁 Actor 可以终结尚未执行的队列节点，但正在执行的 Promise 继续占用原 Actor/Host，实际完成后才释放；同号新 Actor 和新 Runtime 不能被旧完成回调扣减。释放和控制/热更操作不另占普通调用名额；满额时仍能完成旧任务、断线、读状态并在实际排空后恢复。

协议 RPC 保持请求 rpcId 并返回 1011。单向消息没有响应协议：ProtocolRegistry 必须保留过载错误与失败指标，网络边界关闭实际入站来源连接，不能关闭经过路由改写的 context.connectionId，也不能让异常逃出 ordered Runtime Pump。同进程 send 的同步准入失败返回调用者；先进入忙碌 Scene 后才发生的下一跳失败保留日志/失败指标，send 返回仅表示该跳已接受，不是最终送达或业务事务完成。要求结果确认的业务继续用 RPC/幂等/Outbox，不能自动无限重试事实。

Process 固定标签指标覆盖已接受任务数、两级容量、Process 高水位和分别归属两级的拒绝次数；不按 Actor/连接 ID 打标签、不在每个 Scene 重复聚合。观测字段由 TS update JSON 经 Rust health 状态/Prometheus 投影，Rust 改动后重建实际宿主并核对报告哈希。

先补边界反例，再做定向类型/单测与真实 V8/生成协议的容量、拒绝、销毁保留、独立 Process、热更恢复验证，最后跑含 KCP 完整矩阵及 Linux 条件编译。业务 DTO、闭包、ArrayBuffer 的保留和 Scene mailbox 总量另行处理；本项不能替代它们的准入预算。没有新配置、Native schema 或编译时规则，两个 VS Code 插件不需新增 Schema；AI 维护源与实际分发同步运行时规则。

## 边界反例与修复

`temp/v0.7-actor-capacity-first.log` 为 **5 failed/1 passed**，证明旧实现没有新任务准入界限；存量跨 Runtime 计数隔离仍通过。计数挂在原 ActorRuntime 和 ProcessHost，接受前检查、真实完成/未执行节点销毁时原位释放，不再按 Actor 路由查找已重用实例。同步业务抛错也是已接受调用，其名额依原生命周期归还。

加上数量限制后，`temp/v0.7-actor-capacity-delivery-first.log` 为 **7 failed/2 passed**：单向 Registry 把 1011 变成 HandlerFailed 并吞掉，本地 send 同步拒绝也只记录日志。现保留过载类型与失败指标，EntryScene 在物理入站边界处理，RPC 保持关联号，普通业务异常仍保持旧日志语义。`send` 已被第一跳接受后再发生的拒绝不变成成功回执或自动重放。

继续发现三个外壳会将同步过载误报成 MalformedFrame（`temp/v0.7-actor-capacity-envelope-first.log`，**3 failed/9 passed**）；部分批次下一项拒绝时还使此前已开始 Promise 无人观察（`temp/v0.7-actor-capacity-partial-batch-first.log`，**4 failed/9 passed、1 unhandled rejection**）。外壳仅让真实 1011 穿透，批次早退前观察此前结果；各项仍由 Registry 记录失败、原 Actor 统计真实在途，不将批次当成原子事务。

新增错误传播初版也有来源身份缺口：旧连接断开、墓碑过期并出现同号新等待后，迟到过载关闭了新连接，`temp/v0.7-actor-capacity-late-source-first.log` 为 **1 failed/13 passed**。错误回调现和成功响应一样绑定原 AsyncIngressSource，原来源失效或 Scene 已关闭时不再发关闭命令；新等待仍正常响应。不能延长墓碑到永久、清空任务或提前归还在途来绕过。

公开 API 补充反例为 `temp/v0.7-actor-capacity-public-send-first.log`（**1 failed/14 skipped**）：底层 router 已拒绝 1011，但业务的 scene.scenes.send 外层只按 Rust 文本前缀匹配，将有类型的本地过载重映射为 1006。现在保留已有 RpcError(1011)，仍支持 Rust `[scene-overloaded]` 文本、其余错误映射不变；不能拼接假前缀或只验证底层调用。生成协议夹具增加公开 send 的两级拒绝断言。

最终四个相关文件 **42/42**，`temp/v0.7-actor-capacity-focused-final.log`；测试类型检查、注释、Rust format 与固定指标用例通过。测试覆盖 ordered RPC/void FIFO、unordered 两种入口、两级满额/恢复、销毁/同号重建/Runtime 重启、真实关联号、物理来源、各层外壳与公开 API。新指标位于 TS update 的 game 字段，Prometheus 名称为 `tiangz_process_actor_mailbox_tasks_{in_flight,capacity,per_actor_capacity,max_in_flight,actor_rejected_total,process_rejected_total}`，只带 Process 标签，同一次拒绝只增加一个对应计数。
