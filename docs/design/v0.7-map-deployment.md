# G2 地图部署迁移契约

2026-09-26，实施前冻结。复用现有 Process `dataPacks.sources` 与 `RuntimeDataPackRegistry` 的模块命名空间、只读 payload 和启动身份。这里装载的是独立部署 JSON，不是 Luban 玩法表；Core 不增加地图服务或任意 Scene 配置字典。

MMORPG 拥有 `org.tiangz.mmorpg.map-deployment` 包及其强类型 schema：payload `formatVersion=1`，`mapHosts` 按 `sceneName` 关联实例，每项显式 `staticMapIds` 和 `acceptDynamicMaps`。模块校验版本、未知键、实例唯一性、有限数组和有效 ID；声明包时当前 MapHost 必须有对应项，不能因漏写项默默回退。包可以覆盖多进程共享的实例，未在当前进程启动的项保留。

保持原 `staticMapIds` / `acceptDynamicMaps` 接受能力并标记 deprecated，移除时间留待兼容矩阵冻结。不加载该包时继续旧默认 `[]/false`；加载时旧字段若显式存在，必须与模块字段逐项相同（地图 ID 顺序也比较），冲突拒绝启动。Rust 当前会把缺失值投影成 `[]/false`，必须改为保留缺失状态，显式空数组/false 则继续投影；JSON null、负数等原非法值仍拒绝。TS 字段本来可选，其类型形状保持。

包生成由 Examples 的明确构建工具负责，使用模块同一份纯校验函数，`--check` 只比对不写入；包内 contentHash 来自规范输出的 payload，宿主仍核对信封和实际 fileHash。当前宿主不重新计算 contentHash，不能把声明的内容哈希当作签名或外部输入真实性证明。示例正式 setup/build 生成部署包，process 配置引用包，check 核对漂移。部署数据是启动时只读数据，修改后重建相关配置并重启，不通过 Hotfix 在线换拓扑。

首先迁移 `packages/mmorpg/configs/local/all-in-one.json`，保留旧部署样例作为过渡兼容用例，不批量改历史 chaos/生产脚本。插件 Schema 与 Core 注释同步，插件维持自身 0.15.2 版本。迁移后的包配置要求本轮重建的宿主（保留字段缺失信息）；旧 0.6.2 宿主仍只验证旧字段部署，不能因候选源码版本尚未发行冻结就认为旧二进制支持新迁移。

验收：Rust 缺失/显式默认/null 投影；模块纯函数正反例及重复项/双写冲突；正式生成包与 schema 一致；Examples 明确 `TIANGZ_ENGINE_ROOT` 指向本轮宿主，官方 setup/check/build 与相关游戏测试；独立 runtime 夹具验证真实数据包/MapHost 启动。无 Location/MapHost 的简单房间消费者另属 G3，不能被本项替代。生成物必须通过官方工具产生，不手改 Generated。
