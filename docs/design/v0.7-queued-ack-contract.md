# 0.7 排队写确认档位与插件说明

2026-09-26。联合复查发现 Native `@queued` 的补全、Hover、生成注释及宿主 Repository 说明无条件写成“Redis AOF 已确认”，但 DBProxy 已有 `backlog.enqueueAck: memory`，会跳过 AOF 等待。这是契约说明错误，本批不改变存储实现、协议、重试、Repository 选择、默认值或版本号。

## 实际行为

DBProxy `crates/dbproxy-storage/src/backlog.rs` 的 `RedisEnqueueSink::write` 先执行入队 Lua，再按 `EnqueueAck` 分支：默认 `Aof` 调用 `wait_for_local_aof`，`Memory` 直接返回成功；服务器配置枚举同样默认 Aof。`postgresRedis` 后端因此存在两档确认：aof 等 Redis 本地落盘，memory 只确认 Redis 内存，后者崩溃可能丢失尚未落盘的已确认入队。两者均不证明 PG 提交，也不把队列序号保护推广为 queued/CAS/事务混写安全。

协议没有在成功响应中返回确认档位，SDK 和生成器不能从返回成功反推耐久性。`storage.backend: memory` 则是独立的测试后端，只保存在 DBProxy 进程内，不提供上述 Redis 或 PG 持久性。原来的生产写法迁移提示也需明确：停写、积压处理和数据迁移要有整体方案，清库不是生产迁移路径，单独排空积压也不足以定义安全切换。

修正位置为 Native README、codegen 文档字符串、LS 补全/Hover，宿主 Repository 注释、两份 AI 入口及可分发技能约束，以及 DBProxy 协议说明。不手改生成物或锁；Core 继续 0.17.0、VSIX 0.16.0、Developer Tools 0.15.2、AI 0.2.0。
