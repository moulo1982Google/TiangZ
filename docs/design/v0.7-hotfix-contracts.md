# 0.7 Hotfix 行为类检查收敛

2026-09-26 实施前冻结。本步只合并行为类的实例状态/构造/static 禁令，依赖方向、模块级状态和发布指纹仍由各自检查负责，不以这一项宣称所有静态检查已经统一。

## 当前差异

宿主的 hotfix_class_rules.mjs 通过当前 Core 的 TypeChecker 确认装饰器；Developer Tools 的 projectAnalyzer.ts 另有语法规则，会按同名文本识别，甚至包含当前 Core 未导出的历史 actor handler 名称。两边消息和入口范围也不相同。应保留当前 Core 身份与调用方的 TypeScript 版本，不能通过同名装饰器猜测业务类属于框架。

## 唯一规则和适配

规则在 Developer Tools 新的 hotfixStateRules.ts 维护：调用者传 SourceFile、与它匹配的 TypeChecker/TS API、当前 Core 根与诊断根。识别当前 Core 的 hotfixFor/systemFor 以及现有 Handler/实体扩展装饰器，支持导入别名和 namespace。禁字段、构造、static 块和 static 成员；普通实例方法/accessor 允许。保留诊断码 `tiangz.hotfix.instance-state` 与成员位置，确定违反才报 error。

宿主现有文件保留薄适配器，将共享结果转换为既有 1-based 输出；CLI、模块 Host worker 和插件 Program 复用同一实现。共享 Program ruleset 增至 2，插件包版本继续自己的序列。模块检查不重复输出同一错误；生成锁、模块级可变状态和依赖方向仍沿用现有检查，不删除。

仅有语法树、缺少宿主类型环境时，不再用同名文本制造确定性 error。对显式从稳定入口导入的候选行为类，可用同一共享成员检查给出 `tiangz.hotfix.unverifiable` warning，明确需要宿主类型验证；无关本地装饰器不猜测。检查状态 unavailable 与 warning 必须可见，不能把没有 Program 等同于已经检查通过。旧纯语法夹具更新为这种明确的降级语义，真实 Program 负例继续要求 error。

## 验证范围

使用同一批正反例比较共享规则、宿主 TS 6 和插件 TS 5：当前/旧 Core、别名、namespace、同名无关函数、合法方法、字段、构造、静态块/方法、实体扩展 Handler、未解析稳定入口。CLI 与已安装 LSP 必须得到相同确定性规则码和位置，未保存修复后诊断清除；模块实时 worker 仍从已保存声明的 Host 取 Program。

源码先在各自 worktree 修改与构建，显式本地 npm 候选再联合验证；不能靠另一个 checkout 的源码深层导入或改发布依赖锁。更新 AI、规则文档及实际插件制品。无发布或全套规则统一声明。

## 实施与验证

共享规则已接入 Program，原 projectAnalyzer 中约 90 行重复检查删除。主工程默认范围仍是 `app/hotfix` 且排除 bench；模块 Host 显式传声明内的 `hotfixSourceFiles`，支持自定义目录。宿主薄适配保留 1-based 坐标和错误码，模块检查删除重复调用；旧 ruleset 明确报需更新候选，不能静默漏掉新检查。边界验证器把收集到的 Hotfix 文件全部纳入同一 Program，不再把额外创建的语法树配给另一个 checker。
