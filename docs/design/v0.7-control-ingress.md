# 0.7 控制入站共享名额

2026-09-26 冻结实现范围；验收完成后在本文追加实际结果。运行时、生命周期与背压变更，需要完整重建并重启 Process。

## 反例与范围

真实 TS ProcessRuntime/EntryScene 的隔离探针阻塞一个 ordered 断线钩子，按 128 条/轮再注入 520 轮；更新仍保留 66560 条控制节点。放行后 130 轮排空，总计执行 66561 次钩子。`temp/v0.7-control-ingress-probe.log` / `temp/v0.7-control-ingress-audit.json`，命令 `node temp/v0.7-control-ingress-probe.mjs`。没有创建真实连接、Session 或经过 Rust 准入，不能当作网络容量测试。

每轮控制泵上限只限制单次调度，不限制跨轮保留。增加每 Process 共享 **65536** 项未开始控制名额，覆盖 Inner RPC 请求帧和 Disconnect；普通数据保持原暂停注入/字节准入，HostSceneCompletion 和 Shutdown 不竞争这份额度。继续使用原控制通道、公平调度与 13 字节 Host 事件头，不增加游戏协议、配置字段或单独任务调度层。

## 所有权与错误行为

1. ProcessEventSender 在控制入队前取得名额。Inner RPC 即时拒绝，复用现有 SceneOverloaded（1011）回复；断线在现有连接清理路径异步等待，保留原连接/Session 名额，不丢通知、不另建无限等待任务。KCP 沿用 listener 内串行清理的背压语义，不宣称满控制积压下仍继续处理所有 UDP 流量。
2. RAII 守卫随原事件进入 Native 队列、热更延后队列和 Host 批次；批次满退回队首仍保留守卫，编码/发送失败、取消及未发布批次销毁自动释放。
3. V8 take-batch 将守卫转交实际 isolate 的 OpState；字节拷贝/Native 队列出队都不能提前归还。批次交付调用结束清理未被 JS 取走的线程本地批次。预检 isolate 不配置或拥有活动 Process 的名额。
4. TS 控制节点实际进入 processIngress 时归还；若转入忙碌 Scene mailbox，继续持有至真正开始。Scene 关闭、断线后拒绝帧、销毁未执行节点时各归还一次。已经开始的异步业务由既有 ordered/unordered 在途及热更屏障计数，本项不在业务完成时重复归还。
5. 每个 Bootstrap/isolate 的小型确认计数对象绑定至其 ProcessHost，节点始终回到原计数对象；停止后的清理仍可确认，不借全局当前 Runtime 查找所有者。新必需入口 `__etsTakeReleasedControlIngress` 同步返回并清空累计数；Rust 每次 Update 后验证合法整数且不超过已发布数量，然后一次性释放对应数量的同质名额。非法确认不得部分释放。此聚合方式只适用于数量槽，不能用于不同大小/所有者的字节预算。
6. OpState 与接收器销毁均关闭准入，唤醒等待断线的生产者；已发布和未发布守卫分别由原容器释放，不建立 admission→guard→admission 引用环。停止仍使用原总期限，不增加无界等候。

新入口在加载 Model 时强制验证，旧 Model 不能悄悄漏确认后跑满名额。内部 TS `__` 成员不进入 Stable API；不手改任何生成锁。两种 VSCode 插件没有新配置/语法，本轮不更改其版本或包。AI 技能/Cindy 维护源与实际归档随契约更新。

## 指标与验证

固定 Process 指标分别报告保留数、高水位、容量、即时拒绝数、断线等待数，不附加用户/连接 ID。保留数包括尚在 Native、批次与 TS 的未开始控制；等待准入的断线由既有连接容量约束，已开始 Handler、普通数据、完成通知与任意业务对象不计入。

验证顺序：小额度 Native 竞争/取消/接收器关闭/过量确认原子性；真实 V8 的批次转交/开始确认/销毁/失败回收以及满额度完成通知继续；TS ordered 本地忙碌 mailbox、unordered、关闭/销毁/原计数对象的单次归还；真实 Inner TCP 过载/释放恢复和热更停机；最后 Windows 含 KCP 完整 verify、Linux 实际 V8/io-uring/kcp 全目标与 Clippy、AI 官方生成分发及归档检查。不得将单元 Mock 冒充网络，也不得靠增大默认额度或丢掉旧节点让反例通过。

该名额不是 TS 存活 backing buffer、Actor DTO、全部完成消息或 RSS 的上限；单批 64 MiB、Rust 入站字节、Native 批次元数据和其他 mailbox 额度各自有效，不能相加得到精确内存。
