# 0.7 TS mailbox 引用与销毁生命周期

2026-09-26 实施前冻结，属于 N1 的前置修复。任务数、已知二进制成本、控制通知预留及 Process/owner 两级准入仍按[盘点](v0.7-ts-mailbox-audit.md)另行实施；本项不宣称 TS 堆或未执行任务总数有界。

## 引用释放

EntryScene 的 data/control 入站数组、Scene mailbox 和 Actor mailbox 在取出节点时立即清空旧槽。帧或闭包仍由实际执行者持有，不能在开始执行时假定它们已完成；只有队列不再额外保留已交出去的引用。队列原先每 1024 个节点才压缩的策略保持，消费顺序、控制通道公平性及同步执行快速路径保持。

空闲任务节点池每个 Scene/Actor 最多保留 64 个无载荷节点，多余节点交给 GC。此值是复用缓存上限，不是待执行队列上限；不新增部署配置，不宣称是性能最优值。节点的 run/resolve/reject/oneWay 引用均先清空。拥有者销毁清空池，迟到的真实完成不得把节点重新存回已销毁拥有者。

## EntryScene 销毁

清理放在 EntryScene 的内部实体销毁入口，覆盖 ProcessHost 直接销毁和 ProcessRuntime 停机，保持幂等。先关闭 mailbox 准入，再拒绝尚未执行的本地 RPC（SceneNotFound）、丢弃未执行单向工作并记录合计数量，清空入站/出站引用和连接缓存，终结迁移暂存中的等待，最后走原 Entity/Component 级联析构。单向工作不会伪造响应。

已执行的业务 Promise 继续由真实完成路径持有，销毁不是取消其物理 I/O 或回滚其副作用。完成后检查拥有者身份并拒绝返回失效 Scene 的成功结果；不能继续执行已销毁 Scene 的排队业务、重建空闲池或补入出站帧。新本地 RPC 返回拒绝，新的本地单向准入失败同步抛出；进程结束后到达的 Host 事件不重新入队。仍然运行中的业务任务不能因为清空队列就被宣称已经排空。

Actor 原有销毁时移出路由、拒绝待执行调用及运行完成后的身份检查保留，只补齐空槽、空闲池上限和销毁后的引用回收。

## 验证范围

补充冻结：本地 direct Actor 调用和 unordered Scene 调用不能只依靠网络任务或 Timer 的计数间接进入热更屏障。ProcessHost 记录所有已经接受的 Actor 调用（含排队和单向），实际完成或销毁时拒绝未执行节点才归还；销毁路由并不归还仍在运行的调用。EntryScene 记录其实际运行调用，和现有网络任务/队列共同决定 pendingAsync 与 CanCommitHotfix，避免析构或本地路径造成虚假的已排空。计数只用于生命周期，尚不承担额度准入。

用真实 ProcessRuntime/EntryScene/ProcessHost 及协议分发构造可控结果等待，不用 sleep 猜测完成时间。验证有后续帧时旧入站槽已经断开引用；ordered 跨 await 保持顺序；RPC 与单向混合排队不会提前释放运行中任务；突发结束后空闲池不随历史峰值增长；销毁立即拒绝尚未执行 RPC；正在运行的 Promise 直到显式完成仍未终结；迟到完成不执行剩余业务或重填池。保留首次失败证明，再执行类型、完整矩阵及真实 Rust→V8 热更/停机回归。

白盒读取内部队列用于验证持有引用，不向 Stable API 增加调试入口。该证据只说明框架引用关系，不能代替 GC 时机、精确 RSS 或长稳测量。
