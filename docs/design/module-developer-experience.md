# 模块开发体验：框架工具与插件分工

目标：新手可以从真实可运行的小工程理解模块；协作者可以不理解业务规则就找到入口、状态、行为、装配与公开接口。SLG 只作为接入消费者，不以增加玩法替代框架改进。

## 三层职责

| 层次 | 所有权 |
| --- | --- |
| TiangZ Runtime | Scene/Entity/Component 生命周期、装配、消息路由与热更兼容 |
| TiangZ 通用开发工具 | 模板、生成、构建、检查、静态结构解析与工程配置 |
| Developer Tools 插件 | 创建向导、任务入口、导航和错误呈现 |

底层规则只有一个来源；插件可以提示，但不重新决定导入合法性、协议锁变化或热更许可。CLI/CI 用户无需安装插件。AI 解释不得把未解析的动态关系标成确定事实。

## 2026-09-16 本轮已实现

- `modules:inspect`：只读结构输出，复用合法模块目录解析，提供 formatVersion 1 JSON 和源位置；显示状态类型、行为绑定、入口和疑似漏加载。type-only 导入不算装配，动态关系明确保留限制。
- `project:create`：框架自有计数器教学工程，提供同名功能目录、入口说明、协议/SDK、运行配置和真实 RPC 验收。
- `game_project.mjs`：统一 doctor/setup/check/build/host-build/start/dev/smoke/inspect/protocol-update；日常 TS 构建不做 Cargo，协议锁更新显式执行，同工程开发命令互斥。
- `dev_runtime.mjs --project`：复用现有候选发布状态机；已有 Hotfix 行为自动生成候选，失败保持旧版本；Model、协议和声明变化提示重启。结构化候选输出支持含空格的路径。
- `modules:typecheck --json`：提供版本化错误与位置；构建前复用现有 Hotfix 状态边界规则，缺少运行时桥接导出也有明确错误码。
- 桥接预检只使用真实 Core 来源和唯一直接顶层登记，未调用辅助函数不覆盖登记结果；动态装配保留运行时验证，不把不确定关系报告成缺失。
- `module:new-component`：生成同功能目录的 Component/System 并补齐两个入口，支持四文件预览与防过期指纹，拒绝覆盖和动态入口；不擅自决定组件所有者。
- 持续开发：原样保存稳定源码不误报重启；`request` 可观察运行中教学服务的计数变化；SDK 握手取消和旧连接回调清理已有回归。
- 持续诊断：宿主在初始构建及 Hotfix 检查前后输出成对 begin/end，失败也结束检查轮次；插件使用持续任务匹配器，不将检查结束当作 Runtime 就绪。实际编辑器 Problems 刷新仍需人工验收。
- Developer Tools：独立模块树、状态/行为的静态来源关联、读取工程声明、新建工程向导、准备/检查/构建任务和开发模式启动/停止。插件不复制模板和构建实现，任务开始不等于完成；边界错误可在 Problems 定位。

第一批插件导航本地提交 `192eb00`；未发布 Marketplace，也未自动修改用户编辑器安装。后续插件改动以该插件仓库历史为准。TiangZ 主工程保留工作区改动，不自动提交。

## 暂未完成的边界

Rust 二进制裁剪、此入门工作流的 Native 组合、独立模块接入旧 Process 调试管理器、生产部署和真实新手可用性测量均不因模板存在而视为完成。开发模式的 Inspector 仍需显式配置，不宣称自动附加调试器。

独立模块的实时语义诊断尚未接入旧 LSP。存在 tiangz.project.json 时，旧工程树明确转向模块导航和宿主检查，不用只认识 app/ 的索引误报场景缺失；旧检查 CLI 也明确拒绝，避免把未检查当作通过。宿主 check/build 任务仍提供 Problems 文件行列定位。

建议后续进行两项人工验收：有基础 TS 知识且环境就绪的新手在 30 分钟内完成首次请求及行为修改；未参与开发的协作者在 10 分钟内找到入口、状态所有者、实现、公开接口和测试。时间为目标，不是当前实测成绩。
