# 0.7 Native Core 候选联合验收

2026-09-26。前一批 Engine `8d75f9b` 在 Windows/Linux 完整矩阵都使用发布版 Native Core **0.16.0**。本批显式换成 Native 工作树 `508fd68` 的 **0.17.0 Core**，验证真实包、宿主生成/构建和运行，不把先前 0.16 的通过冒充候选结果。VSIX 保持 0.16.0，Developer Tools 0.15.2，AI 0.2.0。

## 输入与隔离

Native 工作树正常 `npm pack --json --pack-destination <独立目录>` 执行正式 prepare 后生成 `tiangz-native-language-core-0.17.0.tgz`，SHA256 `e96104051f9ff9033e84d68ff33ee2bdcac4b6dfb9f72b65b463b4f09579cf12`。实际 tar 内 **43 文件**逐一与该源码/构建物比较，`temp/v0.7-native-core-candidate/identity.json` 保留明细。与已安装 0.16 对比有 13 文件变化，主要是 parser/validator/codegen 的持久化写模式支持、声明与文档；不靠版本字符串确认内容。

安装使用三个明确本地 tgz 一起执行 `npm install --no-save --package-lock=false --no-audit --no-fund`，保持已经验证的 Developer Tools Core/DBProxy SDK 候选，避免只换一个包时 npm 恢复另两个发布依赖。两包原 SHA 分别为 `d2c710718b3683f6a18eaf3e3016e6ef0e717809c58f9fc9796229d303353e15` 与 `9fdc37e598d265c34375f555a3e00aefac7b12f512bb73cf459815cc649645a8`。核对所有 **139 文件**、两个 Native ESM 入口、实际 esbuild，以及 package.json/lock 保持原哈希后才开始验收。npm allowScripts 提示保留，不更换 npm 策略或升级工具。

Windows 在原独立 Engine 工作树安装，前一批所有测试已取得退出码且保存报告后才切换。Linux 使用既有专用 volume、同样三个 tgz；从干净 Engine `8d75f9b` 重新 `git archive`，tar SHA256 `f12ae1067c0f7075e3cb3afb2556d0882d3c875e27a6afeb203d4590a92dfb6f`。正式验证仍是无网络、无端口映射、独立容器的实际 V8/io-uring/kcp；用户服务和已发布依赖锁不变。原生崩溃 ELF/core/历史失败保留。

## 安装校验夹具的失败

初版校验脚本用 `createRequire(...).resolve()` 解析只声明 `types/import` 的 Native ESM exports，Windows 报 `ERR_PACKAGE_PATH_NOT_EXPORTED`，日志 `temp/v0.7-native-candidate-windows-install-check-initial.log`。它选用了 CommonJS 条件，不能因此认定 Native 缺文件或破坏宿主 ESM 兼容。正确验证是在消费项目 cwd 的真正 ESM 子进程 `await import('@tiangz/native-language-core')` 和 `await import('@tiangz/native-language-core/codegen')`；不能给生产包临时添加 require/default 导出或用修改 exports 让夹具通过。安装本身与实际入口检查分别取得退出码，失败后不直接启动矩阵。

Linux 同一夹具错误保留在 `temp/v0.7-native-candidate-linux-setup.log`，npm 安装已完成而后续入口检查失败，不能把整体 exit 1 当作安装未发生并重复初始化 volume。修正纯校验脚本后，两平台 **139 文件、两个真实 ESM import、esbuild 执行、原 package/lock 哈希**均通过且取得 exit 0；日志为 `temp/v0.7-native-candidate-{windows,linux}-install-check.log`。实际版本仍为 TypeScript 6.0.3、esbuild 0.28.2、Vitest 5.0.2。

## 验收范围

保持正式生成器、锁检查、Model/Native 指纹与真实宿主路径；先完成安装身份核对，再运行 Windows `TIANGZ_VERIFY_CARGO_FEATURES=kcp npm run verify` 与 Linux `TIANGZ_VERIFY_CARGO_FEATURES=io-uring,kcp npm run verify`。现有未标记实体应保持生成字节兼容，新增 queued/transactional 的生成对照/TS 类型证据沿用 Native 自身候选测试，实际 DBProxy 恢复测试另有范围，不以此矩阵冒充新写模式的真实存储长稳。
