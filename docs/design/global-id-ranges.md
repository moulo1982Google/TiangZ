# 持久身份与 DBProxy 号段

2026-09-16：这是 TiangZ 通用身份基础，不是 SLG 玩家或合服业务。

## 开发者如何使用

业务仍调用同步 `GlobalIdSystem.Instance.Next()`；恢复已有实体时保留原 ID，不重新发号。部署显式选择：

```json
{
  "process": {
    "name": "game-1",
    "identity": {
      "originServerId": 73,
      "workerId": 2,
      "allocation": "dbproxy"
    },
    "persistence": {
      "dbProxy": {
        "endpoint": "127.0.0.1:7800",
        "authTokenEnv": "GAME_DBPROXY_TOKEN"
      }
    }
  }
}
```

这里省略了游戏自己的 scenes 等配置。首次启动会通过 DBProxy 创建/推进号段记录；这是持久化写入，不是离线检查。运行前必须确认凭据指向正确的租户和权威存储。

`allocation` 省略或为 `local-development` 时保持旧开发行为，并记录“不保证跨重启唯一”的告警，不应承载生产持久身份。启用 `dbproxy` 后不会因连接失败、错误配置或号段不足自动降级；Rust 配置检查会拒绝没有 DBProxy 配置的 dbproxy 模式。

首次号段确认在模块进程配置回调、Scene 构造和 ready 之前完成。领取期间停机不会在迟到响应后继续创建 Scene。业务不配置号段大小，不直接操作号段记录，也不访问 Redis/PostgreSQL。

## ID 不随合服改变

- `(tenantId, GlobalId)` 是租户内的持久身份；不同游戏可以有相同的数字 ID。
- `originServerId` 编入 ID，永久保留且不回收；不能用它推断玩家当前在哪个服。
- `realmId` 是当前归属，由游戏的持久数据和目录维护，不编码回旧 ID。
- `InstanceId` 只属于本次进程运行，重启可重新开始，不作为数据库主键。
- `realmGeneration` 属于切服版本，既不重写 GlobalId，也不替代具体游戏的世界/赛季版本。

本轮没有新增玩家归属目录、迁移器或分服业务。它们需要自己的领域数据和一致性设计。

## 分配机制

复用版本化 SDK 的 Load/SaveSnapshot CAS；DBProxy 不增加游戏 ID 专用协议、表或位布局知识。高水位是普通不透明记录：namespace 为 `tiangz.global-id`，key 为 `<originServerId>:<workerId>`，schema 为 `tiangz.global-id.high-water` 版本 1；payload 为 8 字节大端无符号整数，保存已预留计数的右开边界。

1. 读取高水位，以 `max(高水位, 当前纪元秒 × 4096)` 为起点。
2. 默认一次申请 65,536 个计数，以 expectedRevision 做 CAS。
3. **只有 applied 响应可以授予该号段。** 重复回执可能来自同一槽位的另一个竞争进程，必须跳过；不能把“幂等成功”直接等同于独占号段。
4. 请求号由槽位、旧版本和申请范围确定，载荷/时间戳固定；未知提交结果保留原请求重试。重试若得到 duplicate，整个号段跳过，允许空号。
5. 剩余一半时异步预取，最多一个备用号段和一个在途请求；失败后至少间隔一秒才由后续发号调用触发重试。CAS 竞争每次最多尝试 16 次。
6. 没有本地可用号段时同步抛错，既不阻塞 V8 等数据库，也不伪造成功。大量同步创建可能在异步预取完成前耗尽号段，调用方必须按业务事务边界处理失败，不能把半完成的操作当成功。

布局仍为 `[origin:14][seconds:30][worker:7][sequence:12]`，正数 63 位 bigint。号段计数为 42 位，映射到原 seconds/sequence 位；这两段现在是逻辑计数，不保证等于真实创建时间。时间前移可以跳号，回拨不会回收已领取的范围，计数耗尽时拒绝，不回绕。

## 部署与恢复硬约束

- 同一租户、同一来源/worker 槽位的所有实例必须访问同一权威高水位记录。Endpoint 故障切换必须指向同一存储，不得切换到另一份空库。
- 保留现有静态 worker 去重检查；号段并发安全不等于允许重复 Process/Scene 路由身份。
- 旧墙钟生成器和新号段生成器不能对同一来源/worker 滚动混跑。切换必须先停止并隔离旧发号者，审计已有 ID/时钟情况；必要时使用从未使用过的来源编号。不会自动迁移现有部署或重写玩家 ID。
- 高水位属于不可回退的分配元数据。不得普通快照覆盖、Enqueue、手工删除、租户搬库遗漏或恢复到较旧值。运行中的分配器发现回退/缺失会拒绝，但进程重启后无法仅凭空库识别“首次创建”与“旧库被删除”。
- **不承诺数据库回滚、旧备份克隆、丢失已确认写入后仍唯一。** 恢复必须隔离所有旧分配器，保留高于所有已发/已预留计数的水位，或切换未使用的永久来源编号。号段不能回收，旧进程持有的未消费号段也不能转授。
- 多租户隔离由 DBProxy 凭据绑定负责；保留 namespace 是内部所有权约定，不是额外的权限系统。持有该租户写权限的程序不得擅自写这些记录。
- 生产需要持久 PostgreSQL 后端。内存 DBProxy 只能验证客户端进程重启和并发；重启它会丢失分配记录。

## 验证与兼容

单测覆盖重启、并发、失去提交响应、时钟回拨、耗尽、停机迟到响应、无降级和非法记录。`node tools/global_id_runtime_self_test.mjs` 只启动自有内存 DBProxy 与临时 TiangZ 进程，不接受外部数据库地址；经官方脚手架与构建生成夹具，不手改协议、Bundle 或指纹。

运行该测试前构建 TiangZ 与 DBProxy debug 二进制；真实 PostgreSQL/Redis 重启与故障恢复需要另行在独立可丢弃环境验收。本轮没有操作现有数据库、没有补 SLG Demo。

新增 identity.allocation 配置和启动前异步准备，改变 Core/Model 指纹；升级须完整构建并重启，不可 Hotfix-only。Rust 会在 dbproxy 模式下检查 Model 的号段启动能力标记，拒绝旧 Bundle 静默忽略配置；此标记不是不可信业务代码的安全沙箱。没有新增协议或手改 Stable API 锁；正式发布仍须执行版本/API 锁审核。
