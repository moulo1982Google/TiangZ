# G3 最小房间消费方

2026-09-26 实施前冻结：夹具保存在 Examples，正式 `create_game_module.mjs` 创建一个全新 TS 模块，随后使用现有独立工程 setup/check/build/smoke 链。一个进程只部署一个 `RoomScene`，客户端直接连接该 Scene 的已知 WebSocket 地址；roomId 在该 Scene 的 Component 内 O(1) 查找，不配置 Location/MapHost，也不增加 Core 游戏概念。

Model 的 `RoomStoreComponent` 拥有房间与成员状态，Hotfix System 实现创建、加入、离开和读取重连快照，四个独立 Handler 仅适配协议。一个 Scene 的 ordered mailbox 串行处理这些同步动作。最多 16 房间、每房最多 8 人，空房删除；重复加入返回相同快照，失败不能修改 revision 或已有成员。成员 ID/演示重连凭据有明确长度限制，不输出凭据。

断开连接保留成员，重新连接后使用 roomId/memberId/resumeKey 请求当前快照；这是内存演示，不提供账号鉴权、会话接管 fencing、持久化、服务发现或故障后恢复。旧连接持有相同演示凭据仍能操作，不冒称安全登录。固定容量只限制演示业务集合，不替代运行时内存预算。

夹具用临时目录、动态回环端口和官方生成协议/SDK，保留生成物与日志供核对；无手写 opcode/Generated，无现有 DB 或服务。真实验收覆盖创建、两人加入、断线后新连接快照、错误凭据拒绝且状态不变、重复加入、成员离开和空房失效、另一个房间地址，以及 stdin 正常退出。现有 MMORPG/SLG 的检查和运行证据独立记录，不能用本夹具代替其兼容性。

实际验收：Examples `TIANGZ_ENGINE_ROOT=<本轮 TiangZ-0.7>` 下 `npm run test:room` 通过，9219ms；日志 `v0.7-room-consumer-first.log`。保留工程 `dist/room-consumer-jTQzYi` 的 6 个官方工具日志、生成源码、协议锁和 `acceptance.json`，其中 runtime=true、仅 Room Scene、二进制 SHA256。还覆盖七个并发加入按 mailbox 得到连续 revision、满员后重复加入仍成功、无效创建不占容量、满房数拒绝且既有快照不变。属于直接 Scene 地址与 Scene 内 roomId 路由证明，不把它扩大成跨进程 Actor 迁移证明。
